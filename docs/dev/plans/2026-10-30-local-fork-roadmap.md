## Подготовлено без ручной приёмки

Последующая ручная проверка выявила дребезг system audio с 12 с: прежнее
выравнивание пакетов вставляло/обрезало PCM по колебаниям QPC. Подготовлено
[исправление fidelity](../test-reports/2026-11-01-system-audio-fidelity.md)
с точным сравнением samples. Новый пользовательский повтор 86,369 с не выявил
прежнюю сигнатуру на активном системном звуке; пользователь подтвердил звук
и совпадение A/V. Повтор 56,72 с с pause/resume также проверен, пользователь
подтвердил A/V после Resume. Stop на паузе проверен прогоном 17,66 с;
после перезапуска новая карточка/seek доступны. Прогон 6:26 с idle после 30 с
тоже проверен, пользователь подтвердил A/V и отсутствие выключения экрана.
Затем [проверены Windows default output и контрольный A/V](../test-reports/2026-11-02-capture-device-acceptance.md):
шесть смен с восстановлением и отдельные 43 пары сигнал/вспышка при двух сменах.
Медианы audio−video: +76,693 / +1,693 / +73,359 мс; дополнительного сдвига после
возврата не выявлено с разрешением около кадра (33 мс). Причина базового
запаздывания Voicemeeter этим тестом не установлена. Позднее
[автопрогоны 720p и SRT/VTT](../test-reports/2026-11-02-automated-product-acceptance.md)
подтвердили формат, A/V-маркеры, native importer через IPC и playback/seek
после перезапуска. Субъективное качество 720p остаётся отдельной проверкой;
CPU/RAM позднее измерены отдельным 120-секундным прогоном в полном отчёте.
[Автоматический `.bazza` roundtrip](../test-reports/2026-11-02-bundle-runtime-acceptance.md)
между двумя Windows-библиотеками также прошёл: точные media/metadata, ошибки,
откат, retry/duplicate и native playback/restart проверены на искусственном пакете.
[Полный автоматический отчёт](../test-reports/2026-11-02-full-automatic-acceptance.md)
добавляет получасовой стресс/ресурсы, настоящие file choosers, local models,
Voices и подписочных агентов. Soniox EOS, mic fidelity, process-loopback,
тишина Whisper, ранняя отмена Claude и crash-видео имеют незакрытые дефекты.
Прерванная обработка, отсутствие CLI и restart persistence проверены. Физическая
потеря endpoint, реальные люди/звонки, субъективное качество и macOS открыты.

По следующему поручению пользователя выполнена
[независимая продуктовая работа](2026-11-01-independent-product-work.md).
Сохранение audio scope и endpoint UX, UI FPS/max-height, атомарный `.bazza` и

### Параллельность и общая регрессия

Порядок интеграции: микрофон → recovery → per-app. Mic и per-app меняют общий
native reader и имеют одного владельца; recovery можно исследовать параллельно,
согласовав `recorder.rs`/`pipeline.rs`. Whisper и Soniox допускают независимую
работу в разных модулях с одним владельцем общих ASR/IPC-контрактов.

- [x] Для каждого исправления: воспроизводящий regression test → тесты затронутого
  crate → model/ffmpeg fixture при необходимости → targeted native повтор.
  Использовать [testing.md](../testing.md) и подготовленный локальный toolchain;
  UI/IPC-изменения проверять typecheck и соответствующим Vitest-сценарием.
- [x] После объединения capture/recovery один раз повторить 30-минутный 1080p/30
  сценарий: четыре паузы, Stop на паузе, полный decode, mic/sys/mix, timestamps,
  first/middle/last A/V и ресурсы. Сохранить технический критерий размаха медиан
  ≤40 мс и отдельно измерить постоянный offset, без произвольной компенсации.
- [x] Повторять `.bazza`, SRT/VTT, Voices и agent summaries только при изменении их
  границы либо новом свидетельстве регрессии. Предыдущие успешные результаты
  сохраняют свою область; разные 720p/1080p замеры не считать сравнительным benchmark.
- [x] Закрыть исходный пункт этапа 2 о сравнении прежних и выбранных видеонастроек:
  одинаковый стимул и длительность, сопоставимый фон без параллельных inference jobs;
  сравнить формат, полный decode, A/V, CPU/RAM и сохранение результата. Сохранить
  и восстановить пользовательские настройки. Прежние раздельные 720p/1080p прогоны
  подтверждают каждый режим, но не заменяют это сравнение.

## Исходные этапы и зависимости

Исходный порядок реализации: 0 → 1 → 2 → 3 → 4 → 5 → 6 → 7.
Программные части уже выполнены; ближайшие действия определяет цикл выше.
Первым выполняется baseline существующего приложения. Области этапов 1–2 проверяются
до изменений; их задачи уточняются по подтверждённым пробелам требований и результатам.
После baseline этапы 3 и исследовательскую часть 4 можно выполнять независимо.
Этап 5 использует проверенные временные метки существующего захвата; этап 6
согласует контракты спикеров и моделей с этапом 5. Одновременные изменения IPC,
settings или схемы БД должны иметь одного владельца и последовательные миграции.

Никаких push, PR, удалённых CI, публикации или облачных вызовов в рамках подготовки
плана. Ни один будущий этап не меняет локальный режим разработки R9. Подготовка
изолированного локального toolchain/build разрешена. Пользователь также разрешил
контрольную запись микрофона/системного звука/экрана без паузы и с pause/resume;
испытания выполнены. Затем пользователь отдельно поручил исправить подтверждённые
проблемы; [итоги capture-задачи](../test-reports/2026-11-01-capture-acceptance.md)
включают pause/idle/failure-проверки. Новые продуктовые функции этим не считаются готовыми.

Документация проверяется через `node scripts/check-docs.mjs` и `git diff --check`;
результаты запуска тестов ведутся отдельно от [тест-плана](../test-plans/2026-10-30-recording-baseline.md).

Поручения «испытать без изменения кода» и «выяснить причину рассинхронизации»
выполнены. [Диагностика](../test-reports/2026-10-31-sync-diagnosis.md) установила
per-tick padding в mix и паузу только аудио. По следующему поручению пользователя

Начальный offset и оставшиеся baseline-проверки сохраняют отдельный статус;
новые изменения захвата определять по наблюдаемым результатам.
По мере работы отмечать шаги и реальные проверки в этом плане; подробный план
конкретного большого этапа создавать только при его начале.
