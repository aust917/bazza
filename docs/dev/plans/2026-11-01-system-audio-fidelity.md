# Устранение дребезга системного звука

Статус: complete — исправление и короткий Windows-повтор пройдены.
Короткий ручной pause/resume также пройден; stop на паузе, idle/recovery открыты.
Локальная ветка `codex/pre-acceptance-2026-11-01`.

## Подтверждённый дефект

Ручная приёмка EXE из `2772f8b` выявила дребезг начиная примерно с 12 с,
когда начинается системный источник; голос микрофона до этого нормален.
Исходная 17-минутная контрольная запись сохраняется без изменения.

Численный анализ обнаружил в `sys.wav` короткие нулевые вставки посреди
ненулевого сигнала, в том числе 49/73/74 samples. `mix.wav` сохраняет их;
кодирование AAC и проигрыватель не являются местом появления этих вставок.
`placement()` выравнивал каждый пакет по QPC, вставляя/обрезая samples при
отклонении более 48 samples. Синтетическая непрерывная синусоида с колебанием
QPC на 73 samples воспроизводит порчу при почти правильной общей длительности.

## Исправление и критерии

- [x] Для Windows system loopback использовать stream-relative device frame
  positions из WASAPI, сохранив выбранный endpoint, native format и настройки.
- [x] Привязать временное начало один раз; не редактировать непрерывные samples
  по колебаниям QPC каждого пакета. Сохранить настоящие пропуски native frames,
  паузы и отдельные эпохи при reopen.
- [x] Соблюдать SILENT/TIMESTAMP_ERROR/DATA_DISCONTINUITY; недостоверное время
  показывать как оценочное. Не читать произвольные данные SILENT-пакета.
- [x] Проверить точное сохранение waveform при jitter и разных пакетных границах,
  а не только длительность/частоту сигнала; проверить реальные position gaps,
  сбои, pause/resume и fractional-rate resampling.
- [x] Проверить независимым review, выполнить целевые тесты/Clippy, собрать EXE.
- [x] После подготовки исправления выполнить короткую аппаратную проверку
  с участием пользователя; не считать её пройденной по синтетическим тестам.

## Распределение и ограничения

Clock/worker regression tests и Windows native loopback реализуются отдельными
исполнителями с одним согласованным контрактом. Основной исполнитель сохраняет
доказательства, интегрирует и собирает. Рабочий mic path и macOS не заменяются.
Аппаратную запись для приёмки запускает пользователь; внешние сервисы в
диагностике не запускаются.
Потерянные/обрезанные samples старой записи не объявляются восстановленными.

[Проверки и текущий EXE](../test-reports/2026-11-01-system-audio-fidelity.md).
Пользователь записал 86,369 с: на 23,42 с активного системного звука прежних
разрывов не найдено; пользователь не заметил дребезга и подтвердил совпадение
A/V. Следующий прогон 56,72 с с pause/resume также не выявил прежний дефект,
контейнер/микс проверены, пользователь подтвердил A/V после Resume.
Следующий шаг — Stop на паузе, затем idle/device recovery.
Прежняя запись сохранена без изменений; полная fidelity без внешнего оригинала
и количественный lip-sync/drift не объявляются измеренными.
