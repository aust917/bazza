# Выбор монитора и звук встречи с демонстрациями

Status: active
Owner: Bazza recording

## Видео

При записи с видео пользователь выбирает один полный экран. По умолчанию выбран
основной монитор системы. Смена основного монитора при обновлении списка учитывается,
пока пользователь сам не выбрал экран. Идентификатор проверяется перед началом
записи. Если выбранный вручную экран недоступен, приложение предлагает выбрать другой. Источник
звука выбирается отдельно. Режим «Только звук» доступен без выбора монитора.

Базовая запись одного монитора и звук с текущего микшера проверялись ранее.
Смена топологии и последовательные демонстрации из Meet и Premiere требуют
нативной проверки. [Базовый прогон](../test-reports/2026-11-02-capture-reliability.md).

## Звук

В режиме записи системного звука используется весь звук выбранного выхода.
Старый выбор отдельного приложения больше не влияет на запись. Если звук нужен
из разных приложений, их можно направить на один аудиовыход.

1. Проверить базовый сценарий с микрофоном и одним выходом, через который
   воспроизводятся Meet или Discord и Premiere. Хранить исходные дорожки на общей
   шкале времени. В плеере использовать по одному источнику каждого сигнала.
   Дорожки бота хранить отдельно для имён и распознавания. Показывать потерю
   выбранного устройства, чтобы пользователь мог восстановить маршрут.
2. Для звука, который воспроизводится через несколько выходов, отдельно проверить
   захват этих выходов и синхронизацию между ними. Если один сигнал направлен
   на несколько выходов, выбрать один маршрут. При сбое выбранного источника
   сохранить остальные, показать предупреждение и дать выбрать новый источник.
3. Проверить слышимость комментариев поверх ролика, пики и левый/правый каналы.
   Текущий архив моно. Для сохранения стерео оставить системные дорожки в стерео
   и готовить отдельное моно для распознавания. Сначала устранить возврат
   звука через настройки маршрутизации. Если потребуется подавление акустического
   эха, проверять его отдельно на записи с одновременной речью и сохранять
   исходную дорожку микрофона.
4. Собрать единый текст по микрофону и звуку встречи и демонстраций. Добавлять
   имена из дорожек бота при подтверждённом совпадении. При смешанном аудио
   Meet сохранять разборчивую речь с нейтральной подписью, если источник неясен.
   Сохранять видимые в записи субтитры сразу после остановки. Ручной прогон
   сохранять как отдельную версию.

## Приёмка

- Вручную и из уведомления выбрать каждый из двух мониторов по очереди. Проверить
  исходное и итоговое видео по отдельным движущимся меткам. Повторить со сменой
  основного монитора и отключением выбранного экрана до и во время записи.
- В реальном звонке проверить четыре различимых сигнала. Микрофон коллеги,
  ролик коллеги, свой микрофон и звук Premiere. Подать их отдельно и внахлёст,
  затем переключить демонстрацию и повторить фразу в другой момент. Сверить
  звук у принимающего участника, исходные дорожки, итоговое видео и транскрипт.
  У каждого события должна остаться одна слышимая копия и одна реплика с
  корректной подписью. Проверить синхронизацию по
  [критериям измерителя](../../../tools/bazza-call-acceptance/measure/README.md).

## Проверка исходников

Типы TypeScript, 257 тестов интерфейса и проверка документации прошли.
В Windows отключение или смена геометрии выбранного экрана останавливают
видео после обнаружения и оставляют звук. До обнаружения в локальном
черновике возможны переходные кадры. На macOS экран проверяется при запуске.
Следующая проверка в нативном приложении начинается с двух мониторов и
продолжается звонком с обеими демонстрациями.

Тесты экрана записи проверяют выбор основного монитора из нескольких,
смену основного при обновлении списка и сохранение явного выбора.
