# Исправления по аудиту производительности

Статус: complete. Область: [аудит](../test-reports/2026-11-02-performance-audit.md).
Работа и результаты остаются локальными.

## Результат и границы

Устранить блокирующие native-команды, ограничить параллельные pipeline jobs,
сократить память подготовки WAV и стоимость UI/SQLite. Сохранить данные,
таймлайн, raw/clean, действия пользователя и Windows/macOS guards.
Существующие изменения других задач не откатываются.

## Критерии приёмки

- Долгие экспорт/подготовка AI/данные не занимают главный поток.
- Тяжёлые pipelines выполняются последовательно, дубликат meeting ID не запускается.
- Читатель sidecar обрабатывает только запрошенный диапазон с прежним результатом.
- Индексы добавляются новой миграцией с проверкой существующей БД; retrieval сохраняет ranking.
- Playback обновляет только нужные строки; коррекции, имена и локализация работают.
- Регрессионные тесты и повторные измерения затронутых границ проходят.
- Итоговый EXE/sidecar пересобраны и проверены на Windows в отдельной библиотеке.

## Шаги

- [x] Native: фоновые команды, snooze mutex, общая очередь processing.
- [x] WAV: диапазоны sidecar и потоковая подготовка файлов.
- [x] Store/share: индексы, retrieval lock/top-k, завершение сервера.
- [x] UI: строки транскрипта, Intl, Library reload, streaming chat.

## Решения

Capture callbacks и правила live ASR не меняются без отдельного измерения влияния
на таймлайн. Неограниченная live-очередь (F9) остаётся отдельным риском; ограничение
одновременных тяжёлых jobs снижает конкуренцию за CPU без удаления аудио.
Native Cargo сборки и staging выполняет один интегратор последовательно.
