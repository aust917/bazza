# Бот Google Meet с раздельным аудио в Bazza

3 ноября 2026 года · Техническое исследование

Бот может войти в Google Meet как видимый участник и передавать Bazza аудио отдельных участников. Для локального пилота подходит отдельный бот в Chromium. Главная проверка — получить две чистые дорожки с правильными именами, пока оба человека говорят одновременно. Для нового проекта штатного интерфейса Google для этой задачи нет. Google закрыл регистрацию в Meet Media API и отключит его 15 января 2027 года. [Объявление Google от 28 октября](https://developers.google.com/workspace/meet/release-notes#October_28_2026).

### Что проверить в браузерном боте

В проверенной версии Attendee бот читает декодированные кадры входящего WebRTC-трека и сопоставляет источники `RTCRtpReceiver` с участниками Meet. Если видны несколько известных источников, текущий код выбирает самый громкий и отправляет ему весь кадр. Если сопоставления нет, кадр не отправляется. Поле `timestamp_ms` есть во внешнем API, но сообщение из Chrome до сервиса содержит только ID и PCM. Для синхронизации важны фактическое происхождение таймкода, поведение при смене источника и измеренная точность на двух дорожках. [Привязка кадра в Attendee](https://github.com/attendee-labs/attendee/blob/eaacec16f2939b595f196b3957a717bbb0ed23e9/bots/google_meet_bot_adapter/google_meet_chromedriver_payload.js#L2133-L2244), [сообщение из Chrome](https://github.com/attendee-labs/attendee/blob/eaacec16f2939b595f196b3957a717bbb0ed23e9/bots/google_meet_bot_adapter/google_meet_chromedriver_payload.js#L1405-L1437), [формат внешнего события](https://docs.attendee.dev/guides/realtimeaudio#per-participant-audio-streaming).

В пилоте оператор вручную указывает ссылку и запускает бота с видимым именем **Bazza Recorder**, выключенными камерой и микрофоном. Организатор допускает его по правилам встречи. Meet может автоматически отклонять запросы анонимных гостей и сторонних ботов, поэтому первый звонок стоит провести со специально приглашённым аккаунтом. Тайм-аут допуска, отказ и удаление бота должны быть видны оператору. Захват начинается после допуска и согласования записи с участниками. [Управление доступом к Meet](https://support.google.com/meet/answer/9302870?hl=en), [вход бота в аккаунт](https://docs.attendee.dev/guides/signedinbots).

## Как подключить к Bazza

В Discord уже есть две части для переиспользования. Приложение управляет входом и выходом бота и сохраняет WAV по участникам. Отдельный прототип запускает локальный Whisper на каждой дорожке, объединяет реплики по времени и в контрольном звонке сохранил обе фразы при перекрытии. Пайплайн приложения пока не использует эти дорожки как источник именного транскрипта. Детектор Bazza уже распознаёт окно Meet. [Запись Discord](../../../src-tauri/src/discord_recording.rs), [прототип транскрипции](../../../tools/bazza-discord-probe/src/transcribe.rs), [результаты звонка Discord](../test-plans/2026-11-03-discord-bot-overlap.md), [пайплайн](../../../src-tauri/src/pipeline.rs), [детектор Meet](../../../crates/bazza-detect/patterns.toml).

1. **Отдельный прототип.** На Windows бот получает аудио, локальный приёмник сохраняет WAV и манифест, Whisper строит именной транскрипт. Для Attendee приёмник находится на этой же машине или в той же локальной сети. Облачный STT для прогона не нужен.
2. **Общий формат для Meet и Discord.** Хранить непрозрачный ID участника в пределах встречи, ID сессии или источника, отображаемое имя, смещение относительно начала встречи и диапазоны пропусков. Имена могут совпадать. Переподключение объединяется с прежней дорожкой только при подтверждённом совпадении идентификатора. Текущий Discord-формат использует числовой ID и фиксированные 48 кГц, а Bazza группирует реплики по строковой подписи. [Дорожки Discord](../../../crates/bazza-discord/src/tracks.rs), [группировка и переименование говорящих](../../../crates/bazza-store/src/speakers.rs).
3. **Именной транскрипт.** Распознавать каждую дорожку отдельно и объединять реплики по таймкодам с сохранением перекрытий. Отдельно хранить имя из источника и пользовательское исправление. Пропуск связи и кадры с неопределённым источником отмечать в манифесте. Если остаётся доступен только общий `mix.wav`, для него использовать обычную транскрипцию Bazza и не присваивать имя по догадке. [Обработка текста и аудио](../stt.md), [правила приватности](../../privacy.md).
4. **Подключение к интерфейсу после проверки.** В окне записи пользователь вручную включает бота для выбранной встречи. Интерфейс показывает ожидание допуска, приём аудио, разрыв и завершение. При остановке бот выходит, а при отказе Meet обычная локальная запись может продолжаться. Перед совмещением дорожек с `mix.wav` нужно измерить разницу часов, задержку входа, поведение на паузе и после восстановления связи. [Базовая проверка записи](../test-plans/2026-10-30-recording-baseline.md), [проверки часов захвата](../test-reports/2026-11-01-capture-acceptance.md).

## Контрольный звонок

Подготовить встречу с двумя говорящими на разных устройствах в наушниках. Заранее выбрать для каждого по три короткие фразы с различимыми словами-маркерами. Первые две произнести по очереди, оставшиеся четыре — в двух парах одновременно. Для каждой пары отдельно отметить контрольный интервал перекрытия. Проверить WAV до запуска Whisper, затем сверить именной текст с планом.

| Проверка | Предлагаемый критерий для пилота |
| --- | --- |
| Изоляция | Получены два WAV на одной шкале времени. На обоих есть слышимая речь в каждом контрольном перекрытии. Маркеры каждого участника слышны только на его дорожке. |
| Подписи | Все шесть контрольных реплик сопоставлены с правильным ID. Отдельно записаны потерянные слова, неверные подписи и случаи проникновения чужого голоса. |
| Стабильность привязки | Повтор с одинаковыми именами не объединяет участников. В повторе с выходом и входом новый источник либо подтверждённо связан с прежним участником, либо получает отдельную дорожку. Пропуск аудио виден в манифесте. |
| Ограничения | Повтор с тремя одновременно говорящими, тихой репликой поверх громкой и звуком демонстрации экрана показывает, какие источники реально дошли и были правильно подписаны. Два первых участника задают минимум пилота. |
| Управление | Проверены ручной допуск, отказ, остановка из приёмника и завершение встречи организатором. Видимый бот покидает встречу по остановке. |

В контрольном звонке Attendee сохранил обе дорожки при одновременном воспроизведении двух синтетических голосов. Отчёт фиксирует проверку WAV, сбой выдачи задач на занятые воркеры и ограничения распознавания и синхронизации перед подключением к Bazza. [Результаты пилота Attendee](../test-reports/2026-11-03-attendee-google-meet-pilot.md).
