# Подключение новых ботов Discord в Bazza

Проверено по публичной документации на 3 ноября 2026 года.

Для локальной Bazza первый шаг — пошаговый мастер с короткими переходами в Developer Portal. ИИ может провести пользователя по шагам, а текущая Bazza уже умеет проверять токен, строить ссылку приглашения и выбирать канал. Для команды с двумя параллельными записями самый простой вариант — заранее настроить двух разных ботов на двух доверенных компьютерах. [Текущий мастер](../../../app/src/components/DiscordSettings.tsx) · [Живая проверка с Bazz](../test-plans/2026-11-03-discord-bot-overlap.md#запуск-и-остановка-из-bazza)

## Что позволяет Discord

Discord документирует создание приложения в Developer Portal. У нового приложения автоматически появляется bot user. Кнопка **Bot → Reset Token** выдаёт токен, который портал показывает один раз. В публичном Application API есть чтение и изменение уже существующего приложения от имени бота. Документированного публичного метода создания приложения или выдачи нового bot token в этом API и перечне OAuth2 scopes нет. [Quick Start](https://docs.discord.com/developers/quick-start/getting-started#fetching-your-credentials) · [Application API](https://docs.discord.com/developers/resources/application#get-current-application) · [OAuth2 scopes](https://docs.discord.com/developers/topics/oauth2#shared-resources-oauth2-scopes)

OAuth2-приглашение устанавливает существующего бота. Оно может заранее выбрать сервер и запросить `View Channel` и `Connect`. Установку подтверждает участник сервера с `Manage Server`. Канал выбирается отдельно, а права закрытого канала проверяются после установки. Стандартное приглашение не возвращает токен бота. Для частного приложения установку должен проводить уполномоченный владелец приложения с нужными правами на сервере. [Bot Authorization Flow](https://docs.discord.com/developers/topics/oauth2#bot-authorization-flow) · [Server installation](https://docs.discord.com/developers/resources/application#installation-context)

Для выпуска по кнопке потребовался бы поддерживаемый Discord механизм выдачи приложений и токенов. Вызовы внутренних маршрутов Developer Portal с токеном обычного аккаунта не подходят в качестве основы продукта. Discord отдельно запрещает автоматизацию обычных аккаунтов вне OAuth2 и bot API. Пошаговая помощь пользователю в штатном портале остаётся отдельным сценарием. [Политика Discord об автоматизации аккаунтов](https://support.discord.com/hc/en-us/articles/115002192352-Automated-User-Accounts-Self-Bots)

## Мастер и помощь агента

1. **Создать приложение.** Мастер копирует инструкцию, которую можно вставить в новый чат с ИИ. Агент сразу начинает с первого шага. Если ему доступен браузер, он открывает Developer Portal и заполняет имя Bazza Recorder. Если доступен только чат, агент даёт ссылку и одно ближайшее действие. Пользователь входит в Discord, проходит проверку и сам подтверждает создание приложения с условиями Discord.
2. **Сохранить токен.** Мастер показывает путь **Bot → Reset Token**. Пользователь получает токен в Discord и вставляет его напрямую в закрытое поле Bazza. На этом шаге агенту достаточно знать, что Bazza показала подтверждённое имя бота. Токен, буфер обмена и страница с открытым токеном не нужны агенту. В Bazza уже есть проверка личности бота и сохранение в системном хранилище. [Текущая обработка токена](../../../src-tauri/src/discord_settings.rs)
3. **Добавить на сервер.** Bazza строит ссылку по ID проверенного приложения. Если пользователь заранее вставил ссылку на голосовой канал, мастер может взять из неё ID сервера для приглашения и сохранить канал как ожидаемый. При необходимости пользователь копирует ссылку и передаёт её администратору. После подтверждения мастер проверяет доступ бота и показывает название канала. [Bot Authorization Flow](https://docs.discord.com/developers/topics/oauth2#bot-authorization-flow)

Сам мастер должен работать и без агента. Состояния **«Добавьте бота»**, **«Бот добавлен, у канала нет доступа»** и **«Готово к записи»** позволяют вернуться с нужного шага. При наличии действующего токена пользователь начинает со второго шага. При отказе или ошибке доступ к уже подключённому боту должен сохраняться до успешной замены. Агент может объяснять эти состояния и подсказывать следующий шаг по публичному имени бота и канала.

## Несколько записей на одном сервере

| Вариант | Кто настраивает | Как запускается параллельная запись |
| --- | --- | --- |
| Свой бот для каждого оператора | Каждый владелец создаёт бота, администратор сервера подтверждает установку | Каждый компьютер использует свой токен и выбирает канал в Bazza |
| Боты закреплены за компьютерами | Команда заранее создаёт и приглашает несколько ботов, назначает каждому доверенному компьютеру отдельного бота | Оператор выбирает канал, Bazza использует уже назначенного бота |
| Общий пул под управлением службы | Администратор один раз заводит несколько приложений, приглашает их и подключает к диспетчеру | Диспетчер выдаёт свободного бота для канала, а пользователь запускает запись без доступа к постоянному токену |

Для команды число ботов на сервере определяет максимум одновременных записей в разных каналах. Два канала требуют двух ботов независимо от числа сотрудников. Discord Developer Team позволяет централизовать владение приложениями. Craig документирует отдельного резервного бота Giarc как пример нескольких голосовых ботов на одном сервере. [Voice State](https://docs.discord.com/developers/events/gateway-events#update-voice-state) · [Discord Developer Teams](https://support-dev.discord.com/hc/en-us/articles/34905563063703-Creating-and-Managing-a-Developer-Team) · [Giarc](https://docs.craig.chat/giarc/)

Диспетчер нужен, если запись должны запускать произвольные сотрудники. Он проверяет право на выбранный канал и выдаёт исключительную аренду пары «бот, сервер». После Stop или потери связи бот становится доступен только после подтверждения выхода. Когда все боты заняты, Bazza показывает это и предлагает обычную запись. Постоянные токены хранятся у диспетчера. Вариант с `join_gateway` и передачей параметров голосового соединения позволяет проверить, можно ли принимать аудио непосредственно на компьютере пользователя. Раздельную запись голоса мы проверили на локальном прототипе, а в настольной Bazza Discord подтвердил вход и выход бота. Разделение управления и аудио потребует отдельной проверки DAVE, переподключения и авторизации. [Результаты прогона](../test-plans/2026-11-03-discord-bot-overlap.md) · [Songbird join_gateway](https://serenity-rs.github.io/songbird/current/songbird/struct.Songbird.html#method.join_gateway) · [Discord Voice](https://docs.discord.com/developers/topics/voice-connections#connecting-to-voice)

## Следующий тест

Проверить улучшенный мастер на человеке, который впервые открывает Developer Portal. Затем запустить две записи с двумя ботами в разных тестовых каналах одного сервера и остановить одну. Discord должен подтвердить выход только её бота, а другая запись должна продолжиться. Проверить также передачу приглашения администратору, отказ при закрытом канале и повторное открытие мастера после прерванной настройки.
