## Анонимная разметка и отдельный Ready, schema19

3 ноября 2026 года, Windows. Два закрытых RPC работают в синтетическом сервисе.
Первый принимает bounded staged результат для текущего источника локальной ASR.
Второй переводит встречу в Ready после сохранённого результата разметки или
явного пропуска.

- Кластеры проверяются по каждому segment ID в исходном порядке ASR. Метки
  `Speaker N` назначаются в порядке первого появления. Raw, timing и cleaned
  текст сохраняются. Nullable overlay относится к одному source ID, поэтому
  архивные метки остаются доступны. Обновление проекции и индексов, outcome
  и ротация lease входят в одну транзакцию.
- Применённая разметка без назначенных меток и явный пропуск различаются. Связанные
  query voice caches очищаются только для этой встречи. Saved profiles и
  samples сохраняются. FTS fault проверяет откат транзакции.
- Ready меняет lifecycle revision и сохраняет source, transcript revision,
  claim и срок lease. Cleanup может продолжиться с новым lease. Старый
  lease и попытка перевести Ready в Failed через fatal RPC отклоняются.
  При перезапуске свежий claim получает persisted Ready и флаг cleanup.

## Первый increment: worker/capture handoff

- Append schema **v11**, без изменения migrations v1–v10: registered workers,
  capture leases, sequence mapping и минимальные finalize receipts. Worker session
  связан с authenticated transport PID, OS-random secret hash, capabilities,
  service epoch и TTL. Wire не принимает nominated PID или caller role.
  Credentials редактируются в Debug; plaintext token/fence в DB не сохраняется.
- Lease связывает capture/meeting/session UUIDs, lifecycle generation, service
  epoch и hashed fence. Повтор prepare не создаёт вторую встречу; конфликтующий
  payload не принимается. Одна активная capture reservation на библиотеку.
- Новый Tauri-free [capture-handoff](../../../crates/bazza-capture-handoff/README.md)
  удерживает persistent OS artifact lock. Guard сохраняется до close/join raw
  writers и terminal publication; expiry heartbeat не освобождает lock.
  Owner probe сверяет bounded identity/PID metadata; эта metadata не credential.
- Confirmed-STT journal сохраняет исходные sequenced captions/provenance с framed
  hash chain. ACK выдаётся после sync. Exact retry возвращает прежний digest;
  изменённый complete frame не вырезается. Восстановление допускает только torn
  final frame; complete unacknowledged frame сначала сверяется и sync-ится.
- Versioned terminal manifest содержит фиксированную identity/provider/model,
  duration/end time/status, safe error code, media flags и последний confirmed
  sequence. После close/join caller публикует его атомарно и fsync-ит объявленные
  fixed media files. Manifest immutable; путь, credentials и команды не принимает.
- Пять typed private RPC: register/renew worker, prepare/reattach/finalize capture.
  Они доступны только после Hello, с прежними PID/SID/build/schema/epoch checks.
  Client не зависит от Store/SQLite; forged identity/kind/epoch отбрасывает stream.
  Finalize передаёт **только proof/lease/fence**, не terminal/caption payload.
- [Core](../../../crates/bazza-core/src/worker.rs) сначала проверяет worker,
  затем открывает только свой recording UUID directory. Finalize требует
  освобождённый artifact lock и согласованные durable manifest/journal/provider.
  Одна DB transaction фиксирует raw source/segments, selected-provider provenance,
  lifecycle revision, change events, один waiting_for_worker post-process job
  и минимальный receipt. Inference не запускается.
- Service startup и bounded periodic scan рассматривают pending handoffs.
  Busy owner остаётся живым capture; Free без terminal остаётся pending.
  Sealed terminal потребляется только под acquired artifact guard. Это не
  heartbeat-based orphan recovery. Idle boundary повторно проверяет настоящий
  owner: timeout 250 ms не побеждает monitor interval 500 ms. Waiting native jobs
  сами по себе host не удерживают; monitor drain предшествует release Store owner.
- Live worker после service restart может reattach с исходными credentials;
  generation/raw identity остаются прежними, service epoch меняется. Повтор того
  же reattach после потерянного ACK безопасен. Старый proof не разрешает обычные
  новые mutations. Committed finalize receipt отдельно replay-ится по исходным
  credentials после restart, без старой mutation или повторного чтения файлов.
- Capture ID/receipt сохраняются после meeting purge, без transcript bodies.
  Поздний prepare не воссоздаёт удалённую встречу. Чтение service transcript/summary
  теперь допускает processing/recording, сохраняя write-busy и tombstone checks.

### Capture admission v13

Новая capture сначала reserved. Worker удерживает ArtifactGuard и получает begin
ACK до запуска raw/journal writers; generation при этом сохраняется. Объединённый
unique index запрещает одновременные reserved/capturing leases. V12 migration
сохраняет активные captures как уже начавшиеся, mappings и FK.

Owner metadata служит только rendezvous. Живой guard держит bounded local proof
listener, который проверяется через kernel server PID/current OS user, свежий

Он сохраняет failed card/provider и минимальный receipt `CAPTURE_NOT_STARTED`, не
удаляет FS, не создаёт inference/job и не разрешает reuse capture ID. Exact replay
работает после restart/purge. Startup compensation проверяет old-epoch reserved;
periodic/idle recovery не отменяет reserved. Begun/unsealed capture этим путём
никогда не удаляется или не объявляется aborted по heartbeat.

## Постоянные media gates и физический purge

Новый database-free `bazza-media-gate` хранит zero-byte coordination gate вне
recordings. Windows reader открывает его для чтения с FILE_SHARE_READ, purge —

исходного guard; явного unlock в Drop нет. Unix использует shared/exclusive
nonblocking file locks, но macOS runtime в этой работе не проверялся.

recording/clip/staging/publication bytes и держит до финального DB commit.

отклоняется с сохранением всех bytes. Content-only cleanup сохраняет прежнюю
область и stage locks. Для recording gate используется канонический UUID,
поэтому uppercase legacy SQL UUID не обходит lowercase reader на Windows.
Сам reusable primitive по-прежнему хеширует точный bounded SQL ID без path semantics.

## Schema16: input checkpoint и whole-result automatic cleanup

Интеграция 3 ноября: append v16 хранит immutable capture anchor отдельно от
текущего service-owned checkpoint. Новая запись создаётся в finalize transaction.
Backfill допускает только прежний строгий finalized-capture predicate; текущие
внешние revisions не усыновляются чтением. Старые активные v15 bindings retire,
running jobs становятся Interrupted с новой job revision, старые receipts не
переписываются. `checkpoint_revision` обязателен в lease/input hash и media proof
v2. Renew сохраняет checkpoint; новый принятый результат меняет его.

Private Cleanup Begin/Append/Status/Commit/Abort принимает exact UTF-8 JSON sparse
updates. Prototype bounds: 8 MiB / 10 000 updates, encoded request 32 KiB,
4096 chunks, 16 open uploads / 64 MiB reservations на сервис и TTL один час.
До commit staged text не виден. Проверяются offsets, chunk hashes и полный
body hash, затем bounded decode; UUID/intent/append hashes сохраняются после
удаления payload. Все пять операций проверяют текущего worker перед exact
историческим replay; каждый новый запрос дополнительно требует текущую binding
и фактический expiry. Исторический Open snapshot не обещает текущую authority.

Commit одной IMMEDIATE transaction применяет автоматические overlays и legacy
projection, пересобирает indices один раз и меняет checkpoint/job revision,
internal token/input hash. Claim/fence, attempts и фактический expiry сохраняются.
Duplicate IDs имеют last-wins semantics, отсутствующие ID пропускаются в рамках
этой встречи; manual flags обеих representations, включая manual-empty,
защищены. Automatic-empty/NUL/whitespace сохраняются. Raw, timestamps, speakers,
Soniox/STT provenance, settings, policy voice caches/profiles/samples и media не
изменяются. No-op сохраняет transcript revision, но меняет checkpoint/token/job.
Receipt проверяется до commit. Принятый checkpoint стирает другие staged bodies
старого input; transcript/meeting erase инвалидирует и стирает payload в той же
транзакции с rollback. Retained identities/hashes/receipts не содержат текста.

Целевые проверки прошли: API6, client7, Store cleanup16, checkpoint migration4,

fragment reads и reopen, а также no-op. Первые два сбоя были в fixtures:
некорректные voice sample ID/interval и попытка прочесть giant segment через

native voice validation и прежние лимиты не менялись.
