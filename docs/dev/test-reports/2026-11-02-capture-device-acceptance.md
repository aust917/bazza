# Windows: источники звука, recovery и контроль A/V

Дата: 2026-11-02. Проверки выполнены локально на Windows с записью всех приложений,
Windows-default output и видео 1080p / nominal 30 FPS. Продолжение
[проверок исправления захвата](2026-11-01-system-audio-fidelity.md).

Прогоны относятся к существующему EXE с SHA-256
`F0E88C04C63D965AFB80C6D4984D0954AE8108C4BAB889D6686821AC0982DBBC`.
Временный эксперимент с UI настроек полностью отменён. Текущее состояние кода
и используемый EXE не содержат его изменений.

## Настройки Hark — `3d8e3d97`

107,649 с, Ready, сохранённой ошибки нет. Во время записи пользователь менял
**Settings → System audio (what you hear)**. Это сохранение предпочтений для
следующей записи: активный recorder использует снимок настроек начала записи.
Прогон не является проверкой переключения Windows default output.

Системный сигнал присутствовал в 98,24% окон по 100 мс при пороге −60 dBFS;
тихих интервалов длительностью от 0,5 с не найдено. Mix соответствует mic+sys
с погрешностью не более 1 PCM unit; полное декодирование прошло без ошибок.
На участке 10–40 с прежних резких нулевых вставок — 0 против 120 в исходной
повреждённой записи, по одинаковому критерию: 8–2400 нулевых frames и хотя бы
одна прилегающая граница более 100 PCM units.

Сохранённое значение dropdown и waveform сами по себе не устанавливают
физический endpoint активного захвата. В проверенных кадрах прежнего UI также
не было ясной подписи о применении выбора к следующей записи.

## Переключения Windows — `ce72e0c6`

67,288 с, Ready, сохранённой ошибки нет. В Windows выбранная строка проверялась
по маркеру выбора, а не по наведению указателя:
Voicemeeter Input → CABLE Input → Voicemeeter In 3 → Voicemeeter In 4 →
CABLE In 16ch → PA328QV → исходный Voicemeeter Input.

Лог подтверждает **6 успешных reopen**, 0 ошибок reopen. После каждого перехода
в sys вновь появляется сигнал, в том числе после возврата на исходный выход.
Шесть нулевых промежутков длительностью **0,607–0,996 с** согласуются с переходами.
Пользователь также слышал краткие остановки при переключениях; вклад источника,
маршрута воспроизведения и Hark в их длительность не разделён.

В последнем переходе лог содержит **1 предупреждение alignment** о возможном
пропуске поздних packets. Во всём файле и последних четырёх секундах mix совпадает
с mic+sys в пределах 1 PCM unit; дополнительная потеря значимого архивного сигнала
в mix не обнаружена. Это не исключает потерь до записи RAW.

Возле четвёртого перехода есть единичный abrupt-zero участок 37,56 мс в sys/mix.
Он и длинные switch gaps не подтверждают возвращение прежней частой пакетной
jitter-сигнатуры. Полное декодирование без ошибок, clipping не найден;
video/AAC PTS/DTS монотонны. **A/V после этих переключений не оценивался.**

## Контрольный A → B → A — `60449d18`

92,758 с, Ready, сохранённой ошибки нет. A — Voicemeeter Input,
B — PA328QV (NVIDIA High Definition Audio). Фактические выборы в Windows
наблюдались примерно на 32,2–32,4 и 62,0–62,2 с записи.

Использован существующий искусственный ролик с нерегулярными flash/tone markers.
Видео сопоставлено независимо по вспышкам, аудио — по уникальным частотам.
Все **43 видимых маркера ID 1–43** найдены в sys, mix и AAC; распределение этапов:

| Этап | IDs / количество | Медиана AAC onset − video onset |
| --- | --- | --- |
| A до переключения | 1–12 / 12 | +76,693 мс |
| B | 13–28 / 16 | +1,693 мс |
| A после возврата | 29–43 / 15 | +73,359 мс |

Плюс означает, что аудио позже видео. Аудиодетектор использует окна 5 мс,
видео — шаг около 33,3 мс; знаки после запятой не означают субкадровой точности.
Разность медиан A после/до возврата — **−3,334 мс**, меньше одного кадра:
дополнительного сдвига после возврата на этой точности не выявлено.
Исходный offset порядка +75 мс для цепочки A остаётся измеренным свойством этой
цепочки; его причинность между player, endpoint и Hark не установлена.
Пользователь сообщил, что результат выглядит нормально.

Mix точно равен mic+sys на всех 4 452 382 samples. AAC→mix: correlation 0,99997083,
SNR 42,12 dB; полный decode без ошибок, clipping не найден, PTS/DTS монотонны.
Сохранность всех импульсов не доказывает бесшовность в тихих интервалах между ними.

## Что не выполнено и границы результата

Следующие пункты описывают состояние на конец этих прогонов. Позднее
[технически проверены 720p и импорт SRT/VTT](2026-11-02-automated-product-acceptance.md)
через автоматический harness; native диалоги и субъективная оценка отдельны.

- Автоматический прогон 720p **не начат**: подготовка прервана до Record,
  максимальная высота осталась 1080. Результата приёмки 720p нет.
- SRT/VTT с тремя искусственными репликами и expected JSON только подготовлены;
  [native импорт](../../import.md) этих fixtures ещё не выполнялся.
- Физическая потеря/отключение endpoint, 30-минутный stress, macOS и приёмка
  STT/моделей/диаризации/саммари/базы голосов этими прогонами не покрыты.
- Recovery подтверждён для испытанных Windows default-output transitions;
  универсальная поддержка устройств и нулевая потеря samples при переключении
  не объявляются. В контрольном прогоне после первого переключения видно
  уведомление об успешной смене устройства. Предупреждения о недоступности
  или физической потере источника ещё не приняты.

Доказательства — локальные JSON численного анализа, выбранные UI-кадры и логи:
`audio-sanity.json`, `verification-summary.json`, `audio-markers-*.json`,
`review_video_flash_analysis.json`, `av-comparison-root.json` и timestamp summaries.
Оригинальные WAV/MP4 сохранены без изменений; медиа, производные и runtime/session
state остаются в игнорируемой локальной области. Речь не транскрибировалась,
модели и внешние сервисы для этих проверок не запускались.
