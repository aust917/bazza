# MCP: schema v10 и общее data core

Дата: 2 ноября 2026 года, Asia/Yekaterinburg. Windows/MSVC, локальная работа.
Продолжает [этап 1](2026-11-02-mcp-phase-1.md) и
[план MCP](../plans/2026-11-02-mcp-implementation.md).

Этап 2 реализован на synthetic libraries. Добавлены append schema v10,
transactional domain API в
[Store](../../../crates/bazza-store/src/service_data/README.md) и typed facade
`bazza-core::Repository::data()`. Production GUI/worker cutover не выполнен.
Private RPC по-прежнему предоставляет только hello/status/metadata/shutdown;
public MCP handlers и external grants не включены.

## Проверенная граница данных

- Migrations v1–v9 сохранены. V10 создаёт отдельные service tables; frozen v8
  upgrade/reopen сохраняет все значения 16 старых таблиц и bytes пяти media
  artifacts. Existing meetings получают recorded, включая missing/corrupt media.
  Миграция backfill сохраняет raw, clean, manual/empty overlays, current summaries,
  participants, speaker memory, settings и исходные IDs. Ошибка посередине v10
  откатывает весь append и user_version; исправление причины допускает retry.
- Metadata mutations целевые. Expected revision, actor, semantic change,
  monotonic changes, search update и минимальный dedup outcome фиксируются одной
  `BEGIN IMMEDIATE` transaction. Два concurrent writers с одной revision дают
  один commit и один conflict. Lost-response retry после reopen возвращает
  прежние ID/revision/sequence без повторной mutation. Другой payload того же
  principal/tool/key получает conflict. Successful receipts действуют семь дней
  от исходного commit, не продлеваются retry и не содержат document bodies.
  Argument budget проверяется counting writer до нормализованных копий.
- Text meeting создаётся ready, с optional timed transcript в одной transaction,
  без capture или recording directory. Неверные интервалы и поздний DB failure
  не оставляют частичную карточку. Чтение missing recorded media не меняет kind.
- Transcript sources неизменяемы. Replace архивирует прежний raw/overlay source;
  import/replace пересоздают current segments/chunks/index атомарно. Batch
  corrections сначала проверяет все targets, сохраняет raw и manual empty/reset,
  один раз rebuild chunks, удаляя stale vectors. Permanent delete удаляет current
  и archived payloads/overlays, provider `stt`/`stt_previous` copies, chunks/vectors
  и затронутые citations. State revision/deletion epoch сохраняются.
- Summary replace сохраняет history/provenance; delete удаляет current/history
  и оставляет persistent suppression/generation. Stale generated commit проверяет
  source и target revisions, suppression и auto_replace; manual/external summary
  не перезаписывается автоматически. После transcript delete summary остаётся,
  получает source_missing и новую revision. Legacy origin backfill консервативен:
  недоказанный automatic origin не даёт разрешения на auto_replace.
- Notes persistent, linked и standalone разделены. Explicit association clear
  отвязывает note; meeting deletion удаляет linked notes, сохраняя standalone.
  List выдаёт metadata без больших bodies. Ordinary edits сохраняют shares;
  permanent document deletion отзывает matching publication dependencies,
  meeting deletion — все shares встречи. Managed snapshot publisher ещё этап 6.
- Unified FTS5 индексирует current title, transcript, summary и user notes.
  Effective использует COALESCE, сохраняя пустой manual overlay. Raw explicit;
  identical both hits объединяются. Archives не выдаются default search.
  Snippets ограничены 2048 UTF-8 bytes; нет выдуманных note/summary timestamps.
  Cursor привязан к persistent library scope, query/filter/representation и
  generation; mutation между pages или другой root получает stale conflict.
  Backfill атомарен, partial readiness не объявляется ready; failure сохраняет
  прежнюю complete projection и допускает retry.

## Jobs, файлы и calendar cache

Registry сохраняет waiting_for_worker/queued/running/terminal states, отдельный
cancel_requested, lease/renewal и новый claim token при reclaim. Старый worker не
может finish/publish после expiry/reclaim. Capture и mandatory purge не отменяются
generic cancel. GUI processing/capture пока не подключены к этому registry.

Staging использует generated private paths, bounded writes и claim/generation
checks до и после I/O. Rename и purge проходят вне DB mutex; final publication
visibility фиксируется transaction. Проверено восстановление после rename без
DB ACK и после partial prepared-file write. Per-stage lock исключает позднюю
запись в уже purged candidate. Existing source-parent junction отклоняется;
внешний файл остаётся на месте. Эти примитивы не являются готовым share publisher.

Meeting delete скрывает tombstone и отзывает shares до physical purge. Cleanup
job durable/mandatory; UUID-relative paths проверяются, symlink/reparse деревья
не обходятся. Настоящий Windows handle с share_mode=0 оставляет PURGE_RETRY;
после закрытия handle cleanup завершается. Старый lifecycle generation не может
удалить файлы новой. Candidate paths захватываются до ответа; поздний recreate
документа не подставляет новые artifacts в старую очистку.

Calendar repository атомарно заменяет parsed occurrences одного source,
ключуя source+UID+start. Failure сохраняет last-success cache как stale; reopen
сохраняет события и sync state. Network refresh/parser integration и dispatcher
не запущены этим этапом; календарные secrets/URLs в новой схеме не хранятся.

## Сохранение поведения и следующие gates

Перед работой обновлён [writers audit](../research/2026-11-02-mcp-writer-audit.md)
по итоговому дереву Nemotron/video/performance. Ownership согласован сообщениями
параллельным сессиям. Изолированный lean target, `-j 2`; shared native target,
runtime, default library/pointer и пользовательский GUI не изменялись этой работой.
SHA-256 capture/recording command/state/pipeline и legacy Store db/segments/ai
совпадают с начальным snapshot этого этапа. Запись аудио, ASR/model download,
cloud и новый capture smoke не запускались.

Эти исходники не являются доказательством новой hardware recording acceptance.
GUI всё ещё имеет прямые Store writers без новых revisions/search hooks;
согласованность с ним не обещается до этапа 3. Fixture marker остаётся development
gate, а trusted MutationContext — не external grant.

Domain read DTO не подменяет public API: полные public фильтры, source_uri,
opaque cursor encoding и fragment continuation — этапы 4–5. Internal transcript
pages возвращают целые segments и отказывают при превышении бюджета одним
legacy segment. Private frame остаётся 128 KiB; крупные document bodies нельзя
просто переслать через него без согласованного continuation/staging transport.
History и calendar repositories являются internal reads; public pagination будет
отдельной проекцией. Jobs не dispatch и не удерживают host автоматически.

Следующий этап — stopped-owner baseline/version interlock, полный GUI/worker
RepositoryClient cutover, registered sessions/leases, invalidation и штатный
capture/recovery regression. Public production MCP mutations, share runtime,
macOS native и реальные Codex/Claude Code hosts остаются последующими gates.
