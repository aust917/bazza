## Подготовка нативного окружения

- До подготовки готовый Hark и Rust toolchain в проверенных стандартных местах
  отсутствовали. MSVC, LLVM/libclang, CMake и ffmpeg уже имелись на компьютере.
- Пользователь отдельно разрешил изолированный локальный toolchain и сборку.
- `rustup-init` загружен с официального `static.rust-lang.org`, SHA-256 сверена с
  опубликованной рядом контрольной суммой.
- Rust/Cargo установлены в `.git/local-tools/` с отдельными `RUSTUP_HOME` и
  `CARGO_HOME`, без изменения системного/пользовательского `PATH`.
- Версии: `rustc 1.99.1`, `cargo 1.99.1`, target `x86_64-pc-windows-msvc`.
- Имеющийся ffmpeg `8.0.1` скопирован в игнорируемый sidecar-каталог проекта.

Первая команда `cargo fetch --locked` завершилась exit 101: lockfile требовал
обновления. Проверка показала единственное расхождение — версия **самого Hark**
`0.3.0` в `Cargo.lock` при `0.4.0` в манифесте. Cargo офлайн согласовал одну строку
с манифестом; версии внешних зависимостей не менялись. Исходный lockfile сохранён
локально в `.git/local-tools/Cargo.lock.before-build`.

Это результат проверки воспроизводимости сборки, а не найденная проблема записи.
Текущая подготовка использует release CPU-профиль и существующий
`scripts/prepare-bundle.mjs`; вывод сохраняется локально в `.git/local-tools/`.

## Rust-тесты

После успешного `cargo test --release --workspace --exclude hark --locked --no-run`
(около 1 мин 32 с) выполнены staging runtime и локальный прогон:

```powershell
node scripts/stage-runtime-libs.mjs --profile release
cargo test --release --workspace --exclude hark --locked --offline -- --skip serves_share_page_and_ranged_media
```

Exit 0. Итог: **97 passed, 0 failed, 5 ignored, 1 filtered out**.

| hark-calendar | 3 | 0 |

| hark-detect | 17 | 2 |

| hark-llm | 19 | 2 |
| hark-models | 4 | 0 |
| hark-share | 3 | 0 |
| hark-store | 18 | 0 |

Пять ignored-тестов требуют моделей либо live-доступа к desktop. Опция запуска
ignored-тестов не использовалась. `serves_share_page_and_ranged_media` исключён,
поскольку тест запускает сервер на `0.0.0.0`; LAN listener в этом прогоне не нужен.
Sidecar не содержит собственных тестов. Desktop package `hark` исключён из этой
workspace-команды; готовый EXE ещё не проходил интерактивный тест.

Тесты проверяют DSP, построение аргументов ffmpeg, логику STT/диаризации с fake
backend, хранилище/поиск/голоса, шаблоны и roundtrip пакета. Они не открывали
микрофон, не писали экран и не выполняли облачные/model-запросы. Приёмка реального
захвата и A/V-синхронизации этими результатами не заменяется.

`node scripts/check-docs.mjs` и `git diff --check` проходят. Из production-файлов

## Что пока не проверено

- Реальное одновременное поступление микрофона и системного звука.
- Захват выбранного монитора и полезное содержимое выходного видео.
- A/V-смещение до/после паузы и drift длинной записи.
- Поведение Tauri UI, библиотеки и проигрывателя в собранном приложении.

Запись экрана/микрофона не запускалась: она является отдельным шагом после
подготовки и сигнала пользователя. До воспроизведения проблемы синхронизация
остаётся гипотезой для испытания, а не задачей на исправление.
