# Производительность: исправления и повторная проверка

Дата: 2026-11-02, Asia/Yekaterinburg. Статус: выбранные исправления реализованы,
Windows release EXE и sidecar пересобраны. Основание —
[аудит](2026-11-02-performance-audit.md),
[план](../plans/2026-11-02-performance-fixes.md).

## Изменения

| Аудит | Результат |
| --- | --- |
| F1 | Истёкший snooze очищается с одним guard; тест проверяет повторное применение без deadlock. Текущий UI по-прежнему не предоставляет snooze. |
| F2 | Загрузка LLM, экспорт клипа/HTML, копирование библиотеки, подсчёт размеров и большие чтения Store выполняются вне UI-потока. Холодная LLM загружается одним запросом даже при конкурентных async-вызовах. Остановка share имеет ограниченное ожидание и проверена с непрочитанным media-ответом. |
| F3 | Sidecar читает нужный диапазон WAV; приложение декодирует/ресемплирует файлы блоками. RMS считается потоково. Capture callbacks и параметры записи не менялись. |
| F4 | Startup recovery, post-processing после Stop/импорта, повторная диаризация/транскрипция/embeddings и deferred AI используют одну очередь. Один тяжёлый pipeline активен; повтор одного ID отклоняется. |
| F5 | Строки и JSX транскрипта повторно используются между playback ticks; активная строка ищется бинарным поиском, props Meeting стабилизированы. Полный DOM при первом открытии сохранён. |
| F6 | Новая миграция v9 добавляет индексы папок/тегов; миграции 1–8 сохранены. Проверены upgrade и сохранность данных. |
| F7 | Даты/время используют кэш Intl; reload библиотеки объединяется и не реагирует на одни проценты. Фильтрация выполняется SQL. Исправлен IPC-контракт «Без папки»: `null` — все, `[null]` — без папки, `[id]` — поддерево папки. |
| F8 | Scoped vector SQL использует индекс; scoring выполняется вне Store mutex, читаются партии до 512 кандидатов, сохраняется top-k. Текст извлекается только для актуальных победителей. |
| F10 | Готовые сообщения Markdown мемоизированы; delta объединяются за 50 мс, финал сбрасывает pending buffer без потери текста. |

Очередь не начинает новый job во время активной записи, startup устройств или
Stop/join. Уже работающий pipeline при новом пользовательском старте записи не
прерывается. Удаление встречи резервирует ID и не конфликтует с queued/running
job; mutex очереди не удерживается во время IO. Состояние pipeline сохраняется
частичным UPDATE, поэтому отложенная работа не откатывает название, папку,
участников и другие пользовательские поля. Удалённая строка не восстанавливается.
Копирование библиотеки отдельно защищено от нового capture/import/job admission.

## Транскрипт: тот же production-стенд

Windows, Chromium 156, production React + полные стили приложения. Те же
синтетические русские реплики и callbacks, что в аудите; 12 обновлений позиции
внутри одной реплики, forced layout, auto-scroll отключён.

| Реплик | Обновление p50 до → после | p95 до → после |
| --- | --- | --- |
| 100 | 1,9 → 0,2 мс | 2,4 → 0,2 мс |
| 1 000 | 15,1 → 0,2 мс | 25,0 → 1,4 мс |
| 3 000 | 36,9 → 0,4 мс | 38,1 → 0,7 мс |
| 5 000 | 59,5 → 0,5 мс | 61,5 → 0,8 мс |

Это стоимость обновления компонента, не FPS полного native playback. p95 из 12
измерений фактически равен верхней выборочной величине. Переключение активной
строки, draft коррекции, raw/clean, rename и locale проверены регрессиями.
Первое открытие 5 000 реплик по-прежнему создаёт 51 252 DOM-элемента:
413,7 → 446,7 мс в этих одиночных измерениях. Ускорение первого открытия не
заявляется; виртуализация не добавлялась, чтобы сохранить текущую работу с текстом.

## WAV: память до и после

Тот же синтетический WAV: 600 секунд, mono PCM16, 48 kHz, 57 600 044 байта.
Peak working set приведён в десятичных MB. Sidecar — настоящий release EXE,
завершение на ожидаемой ошибке отсутствующей модели после чтения WAV; inference
не выполняется. Helper — optimized harness с текущими production wav/DSP модулями.

| Операция | До | После |
| --- | --- | --- |
| Sidecar: весь файл | 275,1 MB | 44,7 MB |
| Sidecar: 5 минут | 276,1 MB | 25,5 MB |
| Sidecar: 1 секунда | 275,1 MB | 6,7 MB |
| Подготовка полного PCM приложения | 427,2 MB | 49,7 MB |
| Потоковый RMS | — | 4,8 MB |

Полный PCM содержит те же 9 600 016 samples с flush tail; RMS — 2 401 hop.
На 16/48 kHz fixture проверено побитовое совпадение старой и новой подготовки;
для других проверенных частот — длина и погрешность менее `1e-4`, RMS менее
0,001 dB. Sidecar сравнивается побитово с прежней абсолютной сеткой interpolation
для частот/каналов/целочисленных и float форматов, включая EOF/границы диапазона.
Отдельный тест проверяет, что поздний короткий диапазон не декодирует весь файл.

Ускорение CPU подготовки полного PCM не подтверждено: 3,319 → 3,492 секунды.
Исправление здесь уменьшает память. Для PCM24 префикс пропускается последовательно
из-за несовместимого seek Hound с padded 24-in-32; память остаётся ограниченной,
но быстрого seek для этого формата не заявляется. Одновременный RSS нескольких
inference-процессов и качество распознавания этими измерениями не устанавливаются.

## SQLite и форматирование

Повторный синтетический SQL-only benchmark, 20 000 встреч, по 400 папок/тегов:
счётчики папок 292,327 → 0,701 мс, тегов 427,534 → 0,933 мс. EXPLAIN подтверждает
index lookup. При 50 000 chunks scoped selection: 14,217 → 0,163 мс, отдельно
payload победителей 0,038 мс. Общий поиск: чтение всех payload 105,268 мс заменено
чтением компактных партий 42,825 мс и payload 0,079 мс, без Rust scoring/heap в
этих числах. Это не время ответа UI. Общий exact vector search остаётся O(N).

Русское форматирование 5 000 строк: 378,21 → 9,01 мс в Node/ICU microbenchmark,
вывод совпал. Для 1 000 строк: 69,75 → 1,96 мс. Проверены смена языка и года.
SQL-фильтры сравниваются с прежним алгоритмом на комбинациях all/unfiled/subtree/
tag, одинаковых датах, цикле папок и полных полях встречи; malformed wire inputs
отклоняются. Pagination списка всех встреч пока не добавлена.

## Настоящий native runtime

В отдельной синтетической библиотеке, без `start_recording` и cloud-запросов:

| Долгая команда | Длительность стенда | Параллельных простых команд | `recording_status` p50 / max |
| --- | --- | --- | --- |
| `data_info`, 10 000 служебных файлов | 111,4 мс | 4 | 1,0 / 1,7 мс |
| Экспорт 60-секундного MP3 через настоящий FFmpeg | 616,8 мс | 27 | 1,2 / 3,9 мс |
| Snapshot и копирование библиотеки | 1 136,6 мс | 51 | 1,2 / 1,5 мс |
| Холодная локальная Qwen3 1.7B Q4, подготовка chat | 1 018,0 мс | 45 | 1,4 / 2,5 мс |

HTML с копией media экспортирован за 22,9 мс; он закончился до первого
конкурентного запроса, поэтому overlap для этой команды не заявляется.
MP3 и текстовый sidecar проверены. Chat после загрузки отменён; длительная
генерация не измерялась. Для четырёх восстановленных встреч журнал подтвердил
`max_active=1`, все jobs завершились, файлы сохранены. В этом fixture отсутствует
ASR-модель: сохранено прежнее поведение Ready с сообщением о пропуске этапа.
Это проверка recovery/очереди, не полный model-backed pipeline.

Проверен настоящий IPC `null`/`[null]`/`[id]`: 6 всех, 1 без папки, 1 в выбранной
папке. Все операции оставили recorder в idle. Указатель пользовательской
библиотеки восстановлен побайтно; модели использованы из существующих локальных
fixtures, без скачивания. Первая попытка harness ошибочно ожидала Failed при
отсутствующей ASR-модели; ожидание исправлено на установленное soft-skip поведение,
приложение для этого не менялось. Финальный runtime run прошёл полностью.

## Оставшиеся ограничения

F9 (неограниченная очередь local live ASR) не менялась: удаление preview backlog
без отдельной проверки может нарушить timeline; ограничение тяжёлых pipelines
снижает конкуренцию за CPU без потери аудио. Новый capture/sync алгоритм не вводился.
Первое открытие большого транскрипта и список всех встреч остаются без
виртуализации/pagination. Vector search — best effort при конкурентной перестройке:
изменившиеся победители пропускаются вместо присоединения старого score к новому
тексту; полного snapshot нет. macOS, GPU inference и sustained model stress не
проверены. Обычный большой JS chunk Vite остаётся предупреждением размера.
