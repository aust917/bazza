# Windows: запись готова, плеер показывает 0:00

Дата: 2026-11-02, Asia/Yekaterinburg.

## Причина

У записи длительностью 112,916 с оба файла сохранены. MP4 содержит H.264
1920×1080 и AAC mono 48 kHz; WAV — PCM16 mono 48 kHz. Полное декодирование
`ffmpeg -v error -xerror -i <screen.mp4> -f null -` завершилось с кодом 0.

В журнале Tauri запросы к `mix.wav` и `screen.mp4` отклонены asset protocol.
Локальная Rust-диагностика показала Windows package virtualization: родительская
папка канонизируется в обычный `%APPDATA%\Bazza\recordings`, а существующие
файлы — в `OpenAI.Codex_…\LocalCache\Roaming\Bazza\recordings`.
Разрешение родительской папки не совпадает с физическим путём файлов.
Это наблюдение конкретного запуска через Codex, а не установленный дефект
записи аудио/видео или всех способов запуска Windows-приложения.

## Изменение

[get_meeting](../../../src-tauri/src/commands/meetings.rs) выдаёт asset scope
разрешение на каждый существующий медиафайл перед возвратом пути UI.
Tauri регистрирует и канонический путь самого файла. Guard `has_video`
сохранён: оставленный recovery повреждённый MP4 не публикуется.

[Player](../../../app/src/components/Player.tsx) показывает локализованную ошибку
при отказе загрузки/воспроизведения и обрабатывает отклонение `play()`.
Запоздалый отказ предыдущего источника и `AbortError` при переключении
не помечают новую запись как неисправную. Уже загруженные metadata учитываются
при подписке на события.

не публикуются и не входят в исходники. Подготовленный CDP-проверяющий скрипт
не запускался: автоматическая проверка отклонила запуск с диагностическим портом
(`blocked by policy`). Проверка выполнена через навык `computer-use` без порта.
Пользовательские медиа и БД
не исправлялись, облачная повторная транскрипция не запускалась.

## Отдельный дефект транскрипта

Сохранённые Soniox captions уже содержат разрезанные между репликами слова.
[Response::captions](../../../crates/bazza-asr/src/soniox.rs) создаёт один
финальный Caption на ответ WebSocket и применяет `trim()`, а pipeline
сохраняет captions как отдельные сегменты. Граница ответа может приходиться
на часть слова; обрезка пробелов дополнительно теряет информацию о стыке.
В этой задаче исходный текст не переписывался и Soniox segmentation не менялась.
Для исправления нужен аккумулятор исходных токенов между ответами и отдельные
regression tests на границу слова, финализацию и reconnect.
