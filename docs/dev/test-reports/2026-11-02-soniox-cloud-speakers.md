# Soniox: облачная диаризация и экспериментальная идентификация

Дата: 2026-11-02. **78/78 запросов завершились; качество идентификации не прошло проверку неизвестных голосов.** Приложение, пользовательская библиотека и настройки не изменялись. [План и границы](../plans/2026-11-02-soniox-cloud-speakers.md).

## Решение по результатам

**Soniox Async v5 стоит рассматривать как облачный диаризатор после записи. Использовать его как самостоятельную систему идентификации по голосовой базе или автоматически присваивать имена по аудиопрефиксу пока нельзя.**

Без префикса длинные подкасты дали правильную основную метку во всех 144 наблюдениях реплик. Но это 36 исходных реплик в четырёх акустических вариантах, а не 144 независимые записи. Короткие ответы и режим реального времени заметно слабее. Добавление известных образцов может ухудшить саму кластеризацию: неизвестный `s6` получает имя `s4`, а перестановка тех же образцов меняет результат.

Публичный Soniox API не предоставляет постоянного voice enrollment/voiceprint matching: идентификаторы спикеров относятся к одной записи и могут переставляться между запросами. Поэтому здесь отдельно проверен исследовательский способ совместной кластеризации «образцы + подкаст». Он не является штатной идентификацией Soniox. Источники: [speaker identity и diarization](https://soniox.com/wiki/speaker-diarization), [контракт создания транскрипции](https://docs.soniox.com/api-reference/stt/transcriptions/create_transcription).

## Материалы и протокол

Использован замороженный [русский синтетический корпус](../test-plans/2026-11-02-soniox-voice-corpus.md): шесть TTS-голосов, четыре известных (`s1`–`s4`) и два неизвестных (`s5`, `s6`), три подкаста и четыре варианта каждого. Manifest SHA-256: `a29ae2714b1807e696a6c9ae2691b9e8f9110a67d447ed2761ea1bbdfe8ecf04`. Все 209 хешей исходных файлов проверены до и после тестов.

Запросы используют `stt-async-v5` и `stt-rt-v5`; сохранён настоящий `GET /v1/models`, у этих IDs нет alias. Настройки: русский language hint, диаризация включена, без текстового context, имён участников и подсказок по содержанию. RT передавал PCM16 24 kHz mono блоками по 200 мс с реальной скоростью воспроизведения; endpointing выключен, в конце отправлен EOS и получен `finished`. Это прямой provider-тест, не проверка захвата или текущего streaming-конфига приложения.

| Набор | Запросов | Что проверяется |
| --- | ---: | --- |
| Длинные подкасты без образцов, async | 12 | 2/4/6 голосов × clean/noisy/codec/overlap |
| Те же подкасты с четырьмя образцами | 12 | Имена по независимым известным голосам, неизвестные не зарегистрированы |
| Чистые подкасты, обратный порядок образцов | 3 | Устойчивость идентификации к порядку |
| Монтаж коротких реплик, без образцов / с образцами | 12 | Шесть длин: 0,5/1/2/3/5/10 с; по 12 реплик в запросе |
| Одиночный короткий query + четыре образца | 36 | Шесть длин × шесть голосов, без других query-реплик |

| Всего | 78 | 75 async + 3 RT; ошибок обработки нет |

В каждом запросе с образцами использованы только полные reference-A для четырёх известных голосов: 95,232 с аудио, префикс с паузами 98,982 с. Reference-B и подкастовые реплики не входят в регистрацию. Даже в подкасте с двумя участниками доступны все четыре известных образца, чтобы заметить ложное назначение отсутствующему участнику. Пользовательские записи и настоящие голосовые профили не отправлялись.

## Как считались результаты

Эталон — интервалы размещения исходных WAV-клипов. Они содержат паузы; точной ручной разметки речевой активности нет. Поэтому ниже **не DER, не WER и не биометрическая accuracy**.

- Для диагностики диаризации выполнено оптимальное взаимно однозначное сопоставление cloud-кластеров и эталонных голосов по длительности лексических токенов внутри клипов. Это oracle-сопоставление использует query-разметку, поэтому не доказывает идентификацию.
- Основная метка реплики — кластер с не менее 50% длительности её лексических токенов, без ничьей. Дополнительно считаются все ошибочные token-seconds, чтобы большинство не скрывало меньшие ошибки.
- Для идентификации имена получены **только из интервалов префикса**: минимум 1 с поддержки, минимум 80% суммарной длительности размеченных токенов соответствующего образца, минимум 90% чистоты кластера по длительности токенов всех образцов и уникальный dominant-кластер. Общие/неоднозначные кластеры не получают имя. Правила объявлены до просмотра облачных результатов и не подбирались под ошибки.
- Отсутствие query-токенов считается отсутствием свидетельств, не успешным отклонением неизвестного. Непомеченные токены учитываются отдельно; в этих сохранённых результатах их длительность равна нулю.
- Collar равен нулю. В overlap-вариантах один токен может пересечь два эталонных клипа; ошибки времени на границах и реальная путаница голосов не разделены вручную. Показатель токенной атрибуции для overlap — только диагностический proxy.

Sanity-проверки включают перестановку IDs, неверное известное имя, ложное имя неизвестного, отсутствие/неразмеченность токенов, неоднозначные образцы и запрет утечки query-разметки в именование. Независимая проверка оптимального сопоставления совпала с полным перебором на 400 случайных задачах.

## Диаризация длинных подкастов без образцов

| Async-условие | Кластеров при эталоне 2 / 4 / 6 | Верная основная метка реплики | Верная атрибуция размеченных token-seconds |
| --- | --- | ---: | ---: |
| Clean | 2 / 4 / 6 | 36/36 | 100,00% |
| Noisy, 15 dB SNR | 2 / 4 / 6 | 36/36 | 100,00% |
| Codec, 8 kHz MP3 32 kbps | 2 / 4 / 6 | 36/36 | 100,00% |
| Overlap, сдвиг соседних клипов на 1 с | 2 / 4 / 6 | 36/36 | 95,37% |

Нулевое число ошибок в clean/noisy/codec относится только к этому proxy на синтетическом корпусе. Показатель не оценивает пропущенные слова, истинные речевые паузы или поведение на реальных людях. В overlap по отдельным подкастам proxy равен 96,15% / 95,30% / 94,64%; правильное большинство каждой реплики скрывает внутренние ошибки. Наложение клипов не гарантирует одну секунду одновременно произносимой речи.

| Чистый подкаст, RT | Кластеров / эталон | Верная основная метка | Токенная атрибуция |
| --- | --- | ---: | ---: |
| Два известных | 2/2 | 12/12 | 100,00% |
| Четыре известных | 4/4 | 12/12 | 100,00% |
| Четыре известных + два неизвестных | 4/6 | 8/12 | 66,79% |

В последнем RT-запросе объединены `s1+s3` и `s4+s6`. Суммарный RT proxy по трём подкастам — 89,16%, основная метка 32/36. Это наблюдаемое отличие от async. Официальная документация также рекомендует async для качества и предупреждает о влиянии ранней финализации: [диаризация Soniox](https://docs.soniox.com/stt/concepts/speaker-diarization).

## Идентификация через известные образцы

Таблица использует основной forward-порядок `s1,s2,s3,s4`; reverse — отдельный контроль, не выбранная удачная конфигурация.

| Условие, три подкаста | Верно названы известные | Неизвестные без имени | Неизвестные с ложным именем |
| --- | ---: | ---: | ---: |
| Clean, forward | 32/32 | 2/4 | 2/4 |
| Noisy, forward | 32/32 | 2/4 | 2/4 |
| Codec, forward | 32/32 | 2/4 | 2/4 |
| Overlap, forward | 32/32 | 2/4 | 2/4 |
| Clean, reverse | 32/32 | 4/4 | 0/4 |

Во всех четырёх forward-вариантах неизвестный `s6` ошибочно получает `s4` на обеих своих репликах; `s5` остаётся неизвестным. В clean это 12,12 token-seconds ложного имени и падение числа query-кластеров с шести до пяти, тогда как без префикса их шесть. Reverse возвращает шесть и снимает ошибку. Это свидетельство зависимости от контекста/порядка; один успешный порядок не делает метод надёжным.

В clean/noisy/codec forward основная метка известных реплик верна и ошибочных известных token-seconds нет. В overlap та же таблица большинства скрывает 8,704 token-seconds неверного известного имени и 0,6693 с без назначения; среди неизвестных 13,0593 с ложного имени. Ошибочные фрагменты имени найдены во всех четырёх overlap-репликах неизвестных, хотя по большинству ошибочно названы две. Это ограниченный clip/token proxy с оговоркой о пересекающихся эталонах.

В подкастах с двумя известными участниками имена отсутствующих `s3/s4` не появились. В одиночных коротких запросах чужое имя появляется для `s6` в четырёх случаях; это также отражено в проверке отсутствующих участников.

## Короткие ответы и роль контекста

Монтаж содержит 12 независимых от регистрации реплик: два фрагмента каждого из шести голосов. Soniox видит весь монтаж. Длины — вложенные центральные обрезки тех же исходников, а не новые независимые испытания. В одиночном наборе остаётся один из этих query-фрагментов и четыре полных образца; других query-голосов/реплик нет. 0,5 с WAV не означает 0,5 с произнесённой речи.

| Длина фрагмента | Монтаж без образцов: верные основные метки / 12 | Монтаж с образцами: верно известные / 8 | Монтаж с образцами: ложные имена неизвестным / 4 | Одиночные query: верно известные / 4 | Одиночные query: ложные имена неизвестным / 2 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 0,5 с | 5; ещё 3 без токенов | 6; 2 чужих имени | 1; ещё 1 без токенов | 4 | 1 |
| 1 с | 6 | 8 | 2 | 4 | 1 |
| 2 с | 8 | 8 | 0 | 4 | 1 |
| 3 с | 12 | 8 | 0 | 4 | 1 |
| 5 с | 10 | 8 | 2 | 4 | 0 |
| 10 с | 12 | 8 | 2 | 4 | 0 |

В 0,5-секундном монтаже с образцами две реплики `s4` получили `s2` и `s3`; один `s6` не имеет токенов, другой получает `s2`. В одиночных query `s6` ошибочно назван `s2` при 0,5/1/2/3 с. При 5/10 с все шесть одиночных query получили правильный исход, но это только один коррелирующий фрагмент на голос и длину. В монтаже 5/10 с неизвестный снова получает `s4`, несмотря на успех 2/3 с. Монотонного порога надёжности по длительности этот тест не устанавливает.

## Производительность, стоимость и удаление

75 async-запросов передали суммарно 199,973 минуты аудио с учётом многократного префикса. При двух workers время от начала upload до скачивания transcript составило 4,89–11,29 с, медиана 5,82 с. Оно исключает последующий DELETE и не является гарантией сервиса или чистым временем inference. Три RT-потока передавались параллельно на реальной скорости: 203,97–212,82 с на входы длиной 203,032–211,801 с. Это полная сессия, не измерение задержки появления отдельного слова.

Префикс добавляет 98,982 с к каждому из 57 anchored-запросов: для одиночного короткого query именно он составляет почти весь переданный звук. Суммарно примерно 94,03 минуты — повторяемый префикс.

Ориентир по опубликованной оценке $0,10/ч async и $0,12/ч RT — **около $0,35 за весь эксперимент**. Это расчёт по длительности, не счёт: фактический биллинг токенный, текстовые токены также оплачиваются. Источник: [Soniox pricing](https://soniox.com/pricing).

После каждого async-запроса удалены созданные транскрипция и файл отдельно. Финальный read-only аудит подтвердил HTTP 404 для **150/150 объектов**: 75 транскрипций и 75 файлов. Удалялись только IDs текущего эксперимента. RT завершён штатно. Политика провайдера и отдельное удаление file: [privacy](https://docs.soniox.com/security-and-privacy), [delete transcription](https://docs.soniox.com/api-reference/stt/transcriptions/delete_transcription).

## Воспроизводимость и ограничения

Все локальные доказательства находятся под `.git/local-tests/20261102-soniox-cloud/`:

- `manifest.json`, `manifest-before-isolated.json`, `audio/`: точные входы, хеши, интервалы образцов/query, фиксированные crops;
- `provider-models.json`, `results/`: фактический каталог, request config, ответы, EOS/finished RT, время и результаты удаления;
- `evaluation/summary.json`, `evaluation/cases/`, `evaluation/sanity.json`: раздельные итоги по режиму, длительности, порядку и голосу;
- `run-metadata.json`: Python/Windows, ревизия, хеши инструментов, фактический объём и времена;
- `remote-cleanup-audit.json`: финальная проверка отсутствия всех удалённых объектов.

Инструменты остаются локально в `.git/local-tools/soniox-cloud-20261102/`. Выполнены команды:

```powershell

python .git/local-tools/soniox-cloud-20261102/evaluate.py
python .git/local-tools/soniox-cloud-20261102/run.py audit
```

Второй полный async-запуск переиспользовал 39 завершённых результатов и оплатил только 36 новых одиночных случаев. Автоматических повторов создания job нет. Для анализа сохранённого результата достаточно `evaluate.py` и `verify`; cloud-команды не нужны. Для нового платного эксперимента нужна отдельная папка, чтобы сохранить этот снимок.

Проверки документации прошли: `node scripts/check-docs.mjs` (80 Markdown-файлов) и `git diff --check`; новые untracked-документы дополнительно проверены на trailing whitespace. Оба Python-инструмента компилируются, sanity-проверки и независимая численная проверка отчёта прошли. Приложение не собиралось: изменены только новые исследовательские документы и игнорируемые тестовые инструменты.

Корпус синтезирован Soniox TTS и проверяется Soniox STT: возможная общность особенностей провайдера — дополнительное ограничение. Нет реальных людей, микрофонов/помещений, естественных перебиваний, ручного speech-reference, повторных статистических прогонов, cross-language или macOS-приёмки. Высокие clean-показатели не переносятся автоматически на встречи. Перед выбором для реального продукта нужен независимый размеченный корпус людей; отдельный identity-matcher и любая интеграция этим тестом не реализованы и не приняты.
