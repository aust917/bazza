# Soniox Async + локальная идентификация: сравнение с локальными пайплайнами

Дата: 2026-11-02. [План](../plans/2026-11-02-soniox-hybrid-speakers.md). Эксперимент отделён от приложения: его исходники, настройки, пользовательская библиотека, модели и пороги не изменялись.

**Вывод: гибрид технически работает и выигрывает на чистых синтетических подкастах, но универсального улучшения относительно текущего Nemotron + TitaNet нет. В контрольной сцене настоящих русских голосов с длинным контекстом локальный вариант заметно лучше и не даёт ложных имён. Оснований заменять текущий локальный пайплайн гибридом этот тест не даёт.**

## Проверенная композиция

Сравниваются три акустических цепочки на одинаковых 20 записях:

1. **Гибрид:** Soniox Async v5 → локальный TitaNet Small → существующая локальная база образцов → настоящий Rust matcher.
2. **Текущий локальный:** Nemotron 3 через замороженный production sidecar → тот же TitaNet и matcher.
3. **Прежний локальный:** Pyannote/sherpa через тот же sidecar → тот же TitaNet и matcher.

В отличие от [предыдущего облачного эксперимента](2026-11-02-soniox-cloud-speakers.md), в Soniox **не добавляются голосовые образцы**. Из облака берутся только анонимные метки и времена. Имена выводятся локально. Проверяются компоненты диаризации/идентификации, без ASR-сравнения, caption assignment, UI/IPC, записи, подтверждения имён или изменений приложения.

## Материалы и фиксированный протокол

- Двенадцать сохранённых synthetic podcasts: 2/4/6 голосов × clean/noisy/codec/overlap. Есть четыре известных и два неизвестных голоса.
- Шесть коротких synthetic montages по 12 реплик: 0,5/1/2/3/5/10 с, по два query-фрагмента каждого голоса в записи. Длины — коррелирующие обрезки тех же исходников; они не являются независимыми испытаниями.
- Две уже подготовленные публичные сцены трёх русских актёров: short-only, 39 с, и длинные начальные query-реплики с короткими возвратами, 69,75 с. Три связанных gallery-folds: поочерёдно один актёр неизвестен, два известны. Это три человека и две собранные сцены, не независимые группы участников или естественные встречи.

Восемнадцать Soniox-ответов повторно использованы из замороженного облачного теста. Только две публичные actor-сцены отправлены новыми запросами `stt-async-v5`, без `context`, имён или enrollment. Существующие пользовательские записи не отправлялись. Provenance, OpenRAIL и revision публичного корпуса закреплены в [предыдущем bake-off](2026-11-02-speaker-quality-bakeoff.md) и локальном human manifest.

Все локальные diarizers запускаются заново на тех же сигналах, приведённых FFmpeg к 16 kHz mono PCM16. Для общего identity-этапа каждый backend также пересчитывается заново одним TitaNet artifact; прежние native query vectors не подменяют это сравнение. Независимый byte-аудит подтвердил совпадение общего PCM у локальных прогонов и identity extractor.

**База голосов:** frozen native Voices cache, два независимых образца на известный профиль. Synthetic gallery содержит только `s1`–`s4`, `s5/s6` отсутствуют. Human gallery содержит только двух известных актёров своего fold; третий отсутствует. Эти vectors извлечены прежним native enrollment с тем же совместимым TitaNet и остаются локально.

**Общий query extractor:** anonymous-интервалы одного кластера упорядочиваются и объединяются без повторного захвата пересечений; берутся первые 60 с, минимум 1 с аудио. По эталонной личности ничего не очищается. Для Soniox сначала строится envelope последовательных лексических токенов одного speaker: разрыв при смене метки или паузе больше 0,8 с, без padding. Отдельные subword islands не склеиваются напрямую. Это заранее выбранный экспериментальный адаптер времён, а не новая функция приложения.

**Matcher:** настоящий `bazza_diarize::best_match`, threshold 0,62, существующие profile-specific leave-one-out floors, отказы при недостаточной независимой поддержке или неоднозначности. Raw top-1 не выдаётся за принятое имя. Ни общие, ни профильные пороги под результаты не подбирались.

## Как читать метрики

Для всех backend построен **один общий reference** из интервалов клипов и 10-мс RMS activity proxy: p95−35 dB, floor −55 dBFS, bridge 80 мс, удаление островков короче 50 мс. Истинной ручной разметки речи нет; noisy proxy может считать шум активностью. Overlap-клипы могут считать один момент дважды для разных эталонных голосов. Это не human speech DER, WER или биометрическая accuracy.

Строго верное известное событие требует правильного имени хотя бы на 50% activity и **ни одного фрейма чужого имени**. Неизвестный считается корректно оставленным без имени, только если есть минимум 50% покрытия пригодными embeddings и нет ни одного известного имени. Отсутствие меток/embeddings — unavailable, не успешное отклонение неизвестного. Ошибки даже на малой части события показываются отдельно от majority и длительности, поскольку collar равен нулю и границы могут давать небольшие ошибочные фрагменты.

Имена получены только из gallery и embeddings. Oracle взаимно однозначное сопоставление anonymous-кластеров с эталонными личностями применяется только для отдельной оценки диаризации и никогда не подсказывает matcher правильное имя.

## Результаты

Завершены все **60 backend/recording combinations**: 20 гибридных (18 cached + 2 новых cloud) и 40 новых локальных. С учётом human folds оценены 72 случая, без пропущенных результатов/ошибок движка. 264 пригодных cluster/fold-query решения совпали с реальным Rust matcher, расхождений Python/Rust нет. Отказы по длительности отдельных пулов и отсутствующие native voiceprints учитываются отдельно от engine errors.

### Длинные синтетические подкасты

Во всех трёх clean-подкастах вместе — 32 известных и 4 неизвестных события.

| Цепочка | Кластеров при эталоне 2 / 4 / 6 | Строго верные известные / 32 | Верные известные по majority / 32 | Чужое имя у известного, любое время | Неизвестные без имени / 4 | Неизвестные с ложным именем / 4 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| Soniox Async + локальный TitaNet | 2 / 4 / 6 | 32 | 32 | 0 | 4 | 0 |
| Nemotron + локальный TitaNet | 2 / 3 / 2 | 14 | 14 | 2 | 2 | 2 |
| Pyannote + локальный TitaNet | 3 / 5 / 6 | 26 | 32 | 6 | 1 | 3 |

Неназванные известные: гибрид 0, Nemotron 16, Pyannote 0. У Nemotron две ошибки известного имени и две ошибки на неизвестных занимают majority события; это не только границы. У Pyannote чужие имена затрагивают небольшие части событий: majority остаётся правильным у всех 32 известных и без имени у всех четырёх неизвестных. Строгая таблица намеренно не скрывает эти фрагменты: 8,55 с неверного имени на известных и 7,56 с известного имени на неизвестных по activity proxy.

Шум и кодек ограничивают общий локальный identity-этап: **во всех трёх цепочках 0/32 принятых известных имён**, по 4/4 неизвестных остаются без имени с пригодными common embeddings. Soniox по-прежнему даёт 2/4/6 anonymous-кластеров, но это не делает TitaNet-отпечатки достаточно близкими к clean gallery при неизменённых floors. Порог не снижался.

Overlap оценивается отдельно из-за пересекающихся reference-клипов:

| Цепочка | Строго верные известные / 32 | Верные известные по majority / 32 | Неизвестные с любым ложным именем / 4 | Неверное имя: известные / неизвестные, proxy seconds |
| --- | ---: | ---: | ---: | --- |
| Гибрид | 6 | 32 | 4 | 12,83 / 1,30 |
| Nemotron | 1 | 19 | 1 | 16,36 / 0,97 |
| Pyannote | 6 | 30 | 4 | 27,96 / 4,20 |

Ни у одной цепочки нет majority ложного известного имени на неизвестных в overlap. Однако наличие меньших ошибочных фрагментов нельзя называть безопасной идентификацией. Пересечение клипов и нулевой collar не позволяют отделить все ошибки времён от путаницы голосов без ручной проверки.

### Короткие синтетические ответы без длинного контекста

Каждая строка — один монтаж, восемь известных и четыре неизвестных query-события. Известные ниже считаются по строгому правилу; чужих принятых имён на этих монтажах нет ни у одной цепочки.

| Длина | Гибрид: верно известные / 8 | Nemotron: верно известные / 8 | Pyannote: верно известные / 8 |
| --- | ---: | ---: | ---: |
| 0,5 с | 0 | 0 | 0 |
| 1 с | 0 | 0 | 0 |
| 2 с | 0 | 0 | 0 |
| 3 с | 0 | 0 | 0 |
| 5 с | 4 | 0 | 3 |
| 10 с | 8 | 0 | 6 |

При 0,5 с гибрид корректно оставляет без имени только 1/4 неизвестных, ещё 3/4 unavailable/недостаточно покрыты; у Pyannote 3/4 корректно без имени и 1/4 unavailable, у Nemotron 4/4. При остальных длинах все четыре неизвестных в каждой цепочке остаются без имени с пригодным embedding coverage. Это не доказательство общей способности отвергать произвольных неизвестных: голоса и crops повторяются.

### Контроль настоящих русских голосов

Таблица суммирует три связанных gallery-folds. Для short-only знаменатели 30 известных и 15 неизвестных; для контекстной сцены — 36 и 18, включая шесть известных и три неизвестных начальных длинных события.

| Сцена и цепочка | Строго верные известные | Неназванные известные | Известные с чужим именем, любое время | Неизвестные без имени | Неизвестные с ложным именем | Неизвестные unavailable |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Short-only, гибрид | 0/30 | 30 | 0 | 14/15 | 0 | 1 |
| Short-only, Nemotron | 0/30 | 30 | 0 | 15/15 | 0 | 0 |
| Short-only, Pyannote | 0/30 | 30 | 0 | 15/15 | 0 | 0 |
| С длинным контекстом, гибрид | 8/36 | 23 | 5 | 13/18 | 5 | 0 |
| С длинным контекстом, Nemotron | 36/36 | 0 | 0 | 18/18 | 0 | 0 |
| С длинным контекстом, Pyannote | 11/36 | 17 | 8 | 10/18 | 8 | 0 |

У гибрида в контекстной сцене majority чужого имени есть у двух известных и двух неизвестных событий; всего ошибочное имя занимает по 11,09 proxy seconds на известных и неизвестных. Это не сводится к микроскопическим ошибкам границ. У Pyannote majority верного известного имени — 12/36, majority ложного имени неизвестного — 5/18. У Nemotron неверных name-frames нет.

Если исключить начальные длинные реплики и оставить **только короткие возвраты 0,5/1/2/3/5 с**, результат Nemotron — 30/30 известных правильно и 15/15 неизвестных без имени. Гибрид — 6/30 известных правильно, 20 пропущенных, четыре с чужим именем; четыре из 15 неизвестных имеют фрагмент известного имени, в одном случае это majority. Все эти имена используют накопленную речь кластера, а не только короткий ответ.

Причина провала гибрида видна до matching: Soniox даёт по два кластера вместо трёх актёров в обеих сценах. В short-only один кластер чистый `r1`, другой объединяет `r2+r3`; query scores ниже локальных acceptance floors, поэтому имена отклоняются. В контекстной сцене оба кластера смешаны. Один смешанный кластер проходит как `r2`: score 0,84982 против floor 0,82132 в двух folds и разносит имя `r2` на чужие участки. Для другого top score 0,58347 не проходит даже global threshold 0,62. Простое снижение порога не восстанавливает разделение этих смешанных кластеров.

Для той же сцены Nemotron даёт три кластера, Pyannote — шесть. Сохранённые **настоящие native query-векторы Nemotron** отдельно проверены тем же Rust matcher: все 52 доступных cluster/fold решения совпали с common re-extraction, в том числе 36/36 известных и 18/18 неизвестных на контекстной сцене. Cosine соответствующих native/common vectors — 0,999999337–1. Шесть native vectors в codec-сценах отсутствуют; они отмечены unavailable, без присвоения им успешного unknown rejection. Это поддерживает совместимость главного сравнения с существующей Voices-цепочкой.

## Решение и практическая граница

Гибрид снимает часть ошибок диаризации на длинном чистом synthetic corpus и позволяет использовать нашу локальную базу без передачи образцов в облако. Но он не исправляет низкий recall нынешней идентификации на шуме/кодеке или очень короткой речи. На независимом от Soniox TTS actor-control его anonymous-кластеры хуже текущего Nemotron, что приводит и к пропускам, и к ложным именам.

**Результат не обосновывает замену текущего полностью локального Nemotron + TitaNet гибридом.** Гибрид остаётся технически возможной экспериментальной альтернативой для явно выбранной облачной обработки; универсального победителя на этих небольших разных доменах нет. В приложение ничего не внедрено. Следующий качественный выбор потребует естественных размеченных встреч, большего числа настоящих людей и разделения комнат/микрофонов/сессий.

## Выполнение, производительность и очистка

Общие query-векторы вычислялись на CPU с двумя threads. Локальные subprocesses закреплены на двух логических процессорах `[0,1]`, не двух физических cores; у NeMo четыре внутренних CPU workers ограничены этой affinity. Frozen production Nemotron прошёл 20 файлов за 242,90 с суммарного elapsed, Pyannote — за 392,21 с, включая cold load и встроенные native embeddings. Параллельно работали другие этапы; это не контролируемый рейтинг скорости и не end-to-end время обработки приложения.

Новые cloud-вызовы обработали только 108,75 с публичного query-аудио; старые 18 вызовов не повторялись. После двух jobs отдельно удалены обе транскрипции и оба файла; GET-аудит подтвердил **4/4 HTTP 404**. Ни один enrollment vector или enrollment WAV не отправлен. Изначальные 150 remote-объектов предыдущего эксперимента уже удалены и повторно не создавались.

Все 209 хешей frozen synthetic corpus, входные WAV, gallery caches, модель, source responses и пригодные 192-dimensional query vectors проверены после обработки. Оценщик прошёл 10 sanity-cases; независимая проверка oracle совпала с полным перебором на 500 случайных задачах. Полная численная сверка отчёта пройдена. Все пять Python-инструментов компилируются; `node scripts/check-docs.mjs` проверил 106 Markdown-файлов, `git diff --check` и отдельная whitespace-проверка новых untracked-документов прошли. Приложение не собиралось и не изменялось.

## Ограничения решения

Synthetic corpus создан Soniox TTS, поэтому хороший Soniox STT-результат на нём не является независимой проверкой на людях. Публичный human-control существенно полезнее для проверки переноса, но включает только трёх актёров, связанные folds, собранные реплики и повторные crops. Разделены части исходных записей enrollment/query; независимость сессий записи не установлена. Продолжительность enrollment между актёрами различается.

Ретроспективное объединение до 60 с речи может использовать поздние реплики для имени раннего короткого ответа. Это не измерение мгновенного live-узнавания по первым 0,5 с. В сцене с длинным контекстом первые реплики — query-речь, а не регистрационные образцы и не текстовые подсказки провайдеру.

Сравнение использует сырые acoustic outputs и общий identity-этап, без app consolidation, store provenance, именования/подтверждения и caption assignment. На основном Nemotron-выводе кластеров меньше лимита консолидации; legacy-результаты с большим числом кластеров остаются компонентным историческим ориентиром. macOS и естественные многоголосые встречи не проверены.

## Воспроизводимость

Игнорируемые tools: `.git/local-tools/soniox-hybrid-20261102/`. Доказательства: `.git/local-tests/20261102-soniox-hybrid/`.

- `mainmanifest.json`, `human/manifest.json`: входные WAV/хеши, reference, gallery/folds, frozen protocol и provenance.
- `results/`, `remote-cleanup-audit.json`: два новых cloud outputs и проверка удаления; 18 старых responses читаются по зафиксированным путям/хешам.
- `local/{nemotron,pyannote}/`, `local/run-metadata.json`, `local/shared-pcm-audit.json`: новые raw outputs, native embeddings для отдельного контроля, модель/EXE/DLL identities, CPU affinity, время и PCM-аудит.
- `embeddings/`, `local-gallery.json`, `policy/`, `predictions.jsonl`: выбранные анонимные интервалы, общие query-векторы, локальная gallery и реальные Rust-решения.
- `evaluation/`: общий activity reference, strict/majority/duration scores, разделение условий/длин/folds, sanity и независимый oracle-check.
- `native-compatibility/`: контроль настоящих native Nemotron query vectors против общего extractor и финальных решений; `run-metadata.json` в корне снимка закрепляет хеши всех пяти инструментов и итоговой матрицы.

Команды выполняются из корня репозитория. ML-этапы используют уже имеющийся Python 3.12 `.git/local-tools/voice-bakeoff-20261102/encoders/venv/Scripts/python.exe`; окружения приложения не меняются. Offline-анализ готового снимка:

```powershell
.git/local-tools/voice-bakeoff-20261102/encoders/venv/Scripts/python.exe .git/local-tools/soniox-hybrid-20261102/pipeline.py verify
.git/local-tools/voice-bakeoff-20261102/encoders/venv/Scripts/python.exe .git/local-tools/soniox-hybrid-20261102/evaluate_hybrid.py
```
