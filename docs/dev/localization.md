# Локализация настольного интерфейса

Bazza поддерживает русский и английский интерфейс. При отсутствии сохранённого
выбора используется русский. Язык можно менять в настройках и на первом экране
знакомства с приложением; изменение применяется без перезапуска.

## Хранение и синхронизация

`ui_locale` — отдельный JSON-ключ существующего локального `Store`, а не поле
настроек распознавания `Settings.language`. Отсутствующий ключ означает `ru`;
неподдерживаемое или повреждённое сохранённое значение даёт безопасный `en`.
Неподдерживаемые новые значения отклоняются на границе команды.

`get_ui_locale` и `set_ui_locale({ locale })` проходят через
[ipc.ts](../../app/src/lib/ipc.ts). Сохранения сериализуются в native-состоянии;
событие `ui-locale-changed` с `{ locale }` отправляется после сохранения.
Оно не содержит остальные настройки или секреты. Сохранение обычного снимка
`Settings` не меняет `ui_locale`.

[i18n.ts](../../app/src/lib/i18n.ts) подключает ресурсы до первого рендера каждого
WebView, включая скрытые popup и recordbar. Сначала регистрируется подписка,
потом читается выбор; более новое событие защищено от устаревшего ответа чтения.
Поздний ответ сохранения в [LanguageSelect](../../app/src/components/LanguageSelect.tsx)
также не отменяет более новую смену языка в другом окне.

Native меню обновляется независимо от React. [tray.rs](../../src-tauri/src/tray.rs)
считывает текущий язык и состояния записи/обнаружения внутри единой операции
главного потока и обновляет все пункты. Их идентификаторы и действия сохраняются.

В обычном browser preview `mock.ts` имитирует отдельное предпочтение и событие;
между вкладками обновление передаёт событие `storage`. Это проверка UI, а не
проверка Tauri-хранилища или трея.

## Как добавлять строки

Каталоги находятся в `app/src/locales/en/` и `app/src/locales/ru/`:
`common`, `main`, `meeting`, `recording`, `native`. Ресурсы включены в сборку;
запросов к сервису перевода нет. Используйте семантические ключи через
`useTranslation(namespace)`, включая `title`, доступные имена, placeholder,
состояния загрузки и тексты диалогов приложения. Типы ключей выводятся из
английских ресурсов в `i18next.d.ts`.

Переводите целые сообщения с именованными параметрами. Счётчики передают `count`;
английский каталог содержит `one/other`, русский — `one/few/many/other`.
Проверка каталогов сравнивает сообщения и параметры с учётом plural-форм.
Не сохраняйте результат перевода в React state: храните код/ключ, параметры
и исходную ошибку, чтобы уже видимое сообщение меняло язык вместе с интерфейсом.

Стабильные сообщения native-части имеют `{ code, args, detail, message }`;
`message` сохраняет диагностический английский fallback. `notice` добавляет
`level`. Команды отклоняются таким же объектом. `displayMessage` / `displayError`
переводят известный код; старые сохранённые строки и неизвестные ошибки показывают
исходные технические подробности под локализованным пояснением. Английские фразы
не используются для распознавания типа ошибки. Исторические ошибки и логи
не переписываются.

## Границы данных и оформления

- Язык интерфейса не меняет STT, промпты, ответы AI, настройки захвата, согласия
  на внешнюю обработку или содержимое встреч.
- `speakerLabel` переводит только отображение системного `Speaker N`.
  Редактор, значения merge/rename, сохранение и экспорт используют исходные имена.
  Произвольное имя `Me` не переводится по совпадению текста.
- Названия/описания встроенных шаблонов переводятся по ID только при совпадении
  с исходными метаданными. Пользовательские изменения и тело промпта сохраняются.
- Даты, время и размеры форматируются по выбранному языку; часовой пояс сохраняется.
  Таймкоды, SRT/VTT, машинные числа и `.bazza` от этого не зависят.
- Для обоих языков используется единая типографика без засечек: Manrope для
  основного текста и заголовков, JetBrains Mono для таймеров, кода и технических
  значений. Заголовки имеют вес 600, основной текст — 400, подписи и кнопки —
  500–600. Оба семейства поставляются локально с кириллицей и латиницей;
  выбор языка не меняет семейство шрифта. Декоративный serif удалён.
- macOS получает `en.lproj` / `ru.lproj` с описаниями разрешений. Язык системного
  запроса выбирает macOS; переключатель приложения не меняет язык ОС.

Сайт, установщик, заголовки экспортированных документов, веб-страница получателя
и генерация новых автоматических названий встреч остаются отдельным объёмом.
Текущие сохранённые названия и результаты встреч не переводятся.

## Проверка

Из корня репозитория: `pnpm typecheck`, целевые Vitest-тесты, `pnpm test`,
`pnpm build`. Сценарии синхронизации и plural/fallback находятся в
[i18n.test.ts](../../app/src/lib/i18n.test.ts), проверки переключателя — в
[LanguageSelect.test.tsx](../../app/src/components/LanguageSelect.test.tsx).
Компонентные проверки popup/recordbar проверяют сохранность состояния при смене
языка; тесты спикеров проверяют исходные значения переименования и объединения.

Native-тесты `ui_locale`, `ui_message` и `tray` входят в `cargo test -p bazza --lib`;
подготовка runtime DLL описана в [testing.md](testing.md). Windows и macOS runtime
проверяются отдельно: main/popup/recordbar, скрытие/повторное открытие, restart,
меню трея и native диалоги. Для проверки самого языка реальная запись не требуется.
Для автоматической приёмки native меню можно перед запуском задать
`BAZZA_UI_LOCALE_AUDIT=1`: при обновлении трея в локальном логе появится
`ui-locale-audit` с языком, состояниями и результатами настоящих `MenuItem.text()`.
Без переменной этот trace выключен; он не содержит данных встреч или устройств.
Состояние и ограничения приёмки ведутся в
[плане](plans/2026-11-02-russian-ui-localization.md).
