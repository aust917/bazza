# Проверка подписей при одновременной речи в Discord

Цель пилота — убедиться, что видимый бот в одном серверном голосовом канале записывает две раздельные дорожки на общей шкале времени, а локальный Whisper подписывает каждую реплику именем её источника. Описание вариантов интеграции и ограничений приведено в [исследовании Discord](../research/2026-11-03-discord-speaker-attribution.md).

## Подготовка

1. Выберите отдельный голосовой канал на тестовом сервере и согласуйте запись с двумя участниками. Попросите участников надеть наушники, использовать отдельные микрофоны и отключить посторонний звук. Обозначьте аккаунты P1 и P2. До запуска запишите их Discord ID и отображаемые имена в локальную контрольную таблицу. [Подключение Discord к голосу](https://docs.discord.com/developers/topics/voice-connections#connecting-to-voice).
2. Пригласите собственного тестового бота с `View Channel` и `Connect` к выбранному каналу. Передайте токен локально через переменную окружения `BAZZA_DISCORD_BOT_TOKEN`. Храните контрольные артефакты вне репозитория. Для обеих дорожек используйте одну локальную модель Whisper и явно выберите русский язык. [Разрешения Discord](https://docs.discord.com/developers/topics/permissions), [локальный STT Bazza](../stt.md).
3. Когда участники готовы, вручную запустите приём для выбранного сервера и канала. Убедитесь, что бот появился в канале. Отсчёт ниже начинается после входа бота. Можно использовать общий визуальный таймер или жесты координатора, чтобы отсчёт не попал в голосовые дорожки.

Из корня репозитория соберите прототип командой `cargo build --locked --manifest-path tools/bazza-discord-probe/Cargo.toml`. После сборки выполните команды ниже в PowerShell 7.2 или новее. Укажите числовые ID сервера и канала вместо `GUILD_ID` и `CHANNEL_ID`. Введите токен в скрытый запрос терминала.

```powershell
$discordProbeOutput = Join-Path $env:TEMP ("bazza-discord-overlap-" + [guid]::NewGuid().ToString("N"))
$env:BAZZA_DISCORD_BOT_TOKEN = Read-Host -MaskInput "Токен тестового бота"
try {
    cargo run --locked --manifest-path tools/bazza-discord-probe/Cargo.toml -- record GUILD_ID CHANNEL_ID $discordProbeOutput 90
} finally {
    Remove-Item Env:BAZZA_DISCORD_BOT_TOKEN -ErrorAction SilentlyContinue
}
```

## Контрольные реплики

Каждый участник читает фразу примерно за пять секунд. Между этапами оба молчат. Координатор записывает фактический порядок и приблизительное время. Неудавшееся перекрытие повторяют с теми же фразами и отмечают отдельно.

| Время | P1 | P2 |
| --- | --- | --- |
| 00:05 | «Рубин один. Красный поезд идёт через старый каменный мост.» | Молчит |
| 00:15 | Молчит | «Янтарь один. Жёлтый трамвай сегодня идёт к новому вокзалу.» |
| 00:25 | «Рубин два. Красный поезд идёт через тихую горную долину.» | Молчит первую секунду |
| 00:26 | Продолжает говорить | «Янтарь два. Жёлтый трамвай сегодня идёт через городской парк.» |
| 00:38 | Молчит первую секунду | «Янтарь три. Жёлтый трамвай сегодня возвращается к старому депо.» |
| 00:39 | «Рубин три. Красный поезд идёт через высокие снежные горы.» | Продолжает говорить |
| 00:50 | Молчит | Молчит |

После последней фразы остановите запись через Ctrl+C или дождитесь истечения таймера и выхода бота из канала. Откройте `tracks.json` и прослушайте каждый WAV отдельно до транскрипции. Если один микрофон захватил звук собеседника, зафиксируйте акустическую утечку и повторите эксперимент в разных помещениях.

Запустите локальное распознавание. Если модель находится в другой папке, укажите её фактический путь.

```powershell
$discordProbeModel = Join-Path $env:APPDATA "Bazza/models/ggml-small.bin"
cargo run --locked --manifest-path tools/bazza-discord-probe/Cargo.toml --features transcribe -- transcribe $discordProbeOutput $discordProbeModel ru
```

В `transcript.json` у каждого сегмента есть `user_id`, `display_name`, `start_ms`, `end_ms` и `text`. Whisper может разделить контрольную фразу на несколько сегментов. При проверке учитывайте всё её содержание.

## Критерии результата

- **Дорожки.** Получены два читаемых WAV. В манифесте каждому файлу соответствует ожидаемый ID аккаунта и его имя. На дорожке P1 слышны три фразы «Рубин», на дорожке P2 — три фразы «Янтарь».
- **Время.** Сравните начала и окончания участков речи в секундах от начала WAV. Дорожки имеют одну точку отсчёта. У каждого из двух запланированных перекрытий есть пересечение слышимой речи длительностью не менее двух секунд. В одиночных фрагментах слышен только ожидаемый голос.
- **Текст и подписи.** Сохраните исходный результат локального распознавания. В объединённом по времени транскрипте шесть контрольных реплик привязаны к правильным ID, включая четыре реплики в перекрытиях. Запишите отдельно пропуск или искажение слов Whisper, неверное имя и присутствие чужого голоса в WAV. Пропавшую фразу нельзя засчитать как правильно подписанную.

В коротком повторе можно задать одинаковый отображаемый ник обоим участникам. Сравнивайте ID и файлы, чтобы убедиться, что одинаковые подписи не объединили аккаунты. Отдельный повтор после выхода и возврата одного участника покажет, сохранилась ли привязка его следующих реплик.

Для отчёта достаточно указать версию сборки и модели, количество дорожек, диапазоны двух перекрытий, число правильно подписанных реплик из шести и наблюдавшиеся сбои. Аудио, секреты, настоящие ID и полный текст остаются в локальных артефактах теста.

## Короткий повтор

По одному визуальному сигналу оба участника начинают говорить и продолжают 5–7 секунд. P1 повторяет «Рубин, красный поезд идёт через мост», а P2 одновременно повторяет «Янтарь, жёлтый трамвай идёт к вокзалу». В каждой дорожке и в транскрипте проверьте, что контрольная фраза принадлежит ожидаемому аккаунту и что участки слышимой речи пересекаются не менее двух секунд.

## Локальная проверка прототипа

На Windows тест записи подтвердил, что два кадра одного тика попадают в разные WAV, а интервалы без данных заполняются тишиной на общей шкале. Собранный CLI с локальным Whisper small распознал две синтетические английские контрольные фразы и присвоил им два разных ID при одинаковом отображаемом имени. По уровню сигнала выше −40 dBFS в общих 20-мс окнах измерено 2,1 секунды одновременной активности в WAV.

## Первый звонок в тестовом канале

Свободный разговор длился 90 секунд. Бот сохранил два WAV одинаковой длительности для двух Discord-аккаунтов. Локальная транскрипция вернула 25 сегментов. У каждого ID и отображаемое имя совпали с данными исходной дорожки. Прототип зарегистрировал ноль отброшенных тиков, непривязанных и некорректных кадров.

Сравнение RMS по общим 20-мс окнам показало суммарно 0,66 секунды, когда сигнал на обеих дорожках одновременно достигал −45 dBFS. Этот звонок использовался для проверки подключения и раздельной записи.

## Повтор с двумя контрольными фразами

Бот завершил запись по таймеру и сохранил два WAV по 90 секунд. Whisper small распознал обе заявленные участниками фразы. Маркер «Рубин» оказался только на дорожке одного аккаунта, «Янтарь» только на дорожке второго. Все 16 сегментов результата сохранили ID и имя своих дорожек. Счётчики отброшенных тиков, непривязанных и некорректных кадров остались нулевыми.

На участке 6,82–10,18 секунды, попадающем в интервалы обеих контрольных реплик, в общих 20-мс окнах набралось 2,26 секунды одновременного сигнала выше −45 dBFS. Самое длинное непрерывное окно выше порога заняло 0,62 секунды. Короткий повтор подтвердил раздельное распознавание двух перекрывающихся реплик с паузами между звуками. Полный сценарий с шестью репликами остаётся отдельным тестом.

## Запуск и остановка из Bazza

1. Откройте **Настройки → Discord**, сохраните токен своего бота и выберите обычный голосовой канал. Для закрытого канала проверьте права просмотра и подключения.
2. Откройте окно записи, включите **«Имена из Discord»** и нажмите **«Записать»**. Проверьте, что бот появился именно в выбранном канале и панель записи показала подключение. Для этой проверки достаточно пустого тестового канала.
3. Нажмите **«Стоп»**. Проверьте, что бот вышел из канала, Bazza сохранила обычный `mix.wav`, а в папке встречи появился `discord/tracks.json`. Если участники говорили, в `discord` должны появиться отдельные WAV и имена для каждой дорожки.
4. Повторите с выключенным переключателем. Бот должен оставаться вне канала. Для проверки отказа используйте канал, у которого с момента выбора отозваны права бота. Bazza должна сообщить об ошибке Discord и сохранить обычную запись.

Windows, 3 ноября 2026 года. Нативный прогон в изолированной библиотеке вызвал те же команды, что мастер и окно записи. Он сохранил токен Bazz, нашёл сервер и канал, выбрал канал и запустил запись. Discord подтвердил, что Bazz вошёл в выбранный канал после запуска и вышел после остановки. Bazza сохранила `mix.wav` и `discord/tracks.json` с причиной `stopped_by_operator`. Голосовых кадров в этом коротком прогоне не было. В отдельном прогоне с недоступным каналом Bazza сообщила об отказе Discord, продолжила локальную запись и сохранила `mix.wav`.

## Параллельная запись в двух каналах

1. Подготовьте два разных голосовых канала одного сервера и две независимые библиотеки Bazza. Подключите к каждой своего бота через **Настройки → Discord**. Для нового бота можно скопировать инструкцию для ИИ из мастера. Пользователь сам вставляет токен в Bazza и подтверждает установку на сервере.
2. Согласуйте запись с участниками. Включите **«Имена из Discord»** в обеих библиотеках, запустите записи и дождитесь появления каждого бота в выбранном канале. Пока идут обе записи, в первом канале произнесите «Маяк», во втором — «Компас». Участники используют наушники и отдельные микрофоны.
3. Остановите первую запись. Первый бот должен выйти, а второй — остаться в своём канале. Попросите участника второго канала произнести «Компас после остановки» и затем остановите вторую запись. Убедитесь, что второй бот тоже вышел.
4. В обеих папках встреч проверьте `mix.wav` и `discord/tracks.json`. Сопоставьте WAV из папок `discord` с ID участников. На дорожке первого канала должен прозвучать «Маяк», на дорожке второго — обе фразы с «Компасом». Если каналы были пустыми, по прогону можно подтвердить подключение, независимую остановку и сохранение файлов.

Windows, 3 ноября 2026 года. Два изолированных экземпляра Bazza записывали локальное аудио одновременно около двух секунд. После остановки первого второй продолжал запись. В обеих библиотеках сохранены валидные `mix.wav`. Этот контрольный прогон был без подключения к Discord.

В живом прогоне две Bazza удерживали подключения разных ботов к двум голосовым каналам одного сервера в течение 60,18 секунды. Discord подтвердил выход первого бота, а второй оставался в своём канале и продолжал запись ещё 9,24 секунды. После второй остановки оба бота вышли, обе встречи сохранили `mix.wav` и по одному отдельному Discord WAV с ненулевым сигналом.

Один участник переходил между каналами. В первой записи сохранено 350 голосовых кадров, во второй — 581. Во второй записи один кадр остался без привязки, пропущенных тиков в обеих записях не было. Локальный Whisper вернул 12 сегментов, ID и имя каждого совпали с данными его исходной дорожки. Контрольные слова в транскриптах не найдены. Прогон подтвердил независимую запись в двух каналах при переходе участника между ними. Проверка одновременной речи двух участников в разных каналах остаётся отдельным сценарием.
