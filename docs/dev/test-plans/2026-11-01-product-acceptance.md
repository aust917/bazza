# Приёмка подготовленных продуктовых изменений

Статус: частично выполнено; [итоги Windows/A/V на 2026-11-02](../test-reports/2026-11-02-capture-device-acceptance.md).
[Автопрогоны 720p и SRT/VTT](../test-reports/2026-11-02-automated-product-acceptance.md)
прошли техническую приёмку. Субъективное качество/нагрузка 720p, native диалоги,
физическая потеря endpoint и модельные/сервисные испытания открыты.
Основа: [план независимой работы](../plans/2026-11-01-independent-product-work.md).
Автоматические проверки не означают успешной записи или качества моделей.

## Локальная запись и библиотека

Использовать отдельную контрольную библиотеку. Модели и внешние провайдеры для
первых шагов не нужны. Запись начинается отдельным действием пользователя
либо агентом по его поручению для подготовленного технического прогона.

Пользователь делегировал агенту рутинные UI-действия и запуск подготовленных
технических прогонов на втором мониторе; субъективная оценка качества остаётся
за пользователем. Полная инструкция с наблюдениями выдаётся до прогона.
Детерминированные проверки выполнять автоматическим harness через native IPC
и media API; физическое управление UI оставлять для проверки самого интерфейса.
Найденное отклонение не даёт разрешения менять код без обсуждения.
Источник в Settings выбирается для следующей записи; проверка Windows default
output требует менять выход в Windows, сохраняя в Hark System default output.
15 FPS/1080 в начальном шаге ниже — исходный baseline; принятые здесь прогоны
использовали выбранные пользователем 30 FPS/1080, сбрасывать их ради плана не нужно.

1. В Settings оставить локальный STT и исходные 15 FPS/1080. В picker выбрать
   «все приложения» и проверить название output endpoint. Записать контрольную
   речь с микрофона, собеседника и второе приложение на том же выходе.
2. Проверить отдельные источники, предупреждение о потере устройства и его
   восстановление; повторно открыть picker и убедиться в сохранении выбора.
   Захват других физических выходов одновременно этим тестом не обещается.
3. Открыть новую запись, проверить звук/экран и seek. Перезапустить приложение,
   открыть ту же библиотеку, повторить playback/seek старой и новой записи.
4. Проверить выбранные 30 FPS/720 и вернуть исходные значения. Убедиться через
   свойства медиа, что параметры применились; измерить A/V и нагрузку.
   Формат, временные метки, A/V-маркеры и playback/seek после перезапуска
   автоматически проверены 2026-11-02; нагрузка и субъективная оценка открыты.
5. Для дальнейшей длинной проверки предлагается 30 минут, несколько пауз и
   stop на паузе. Длительность и допустимое смещение согласовать до объявления
   качества принятым; не исправлять offset произвольной константой.

## Обмен и голосовые образцы

1. Экспортировать готовую встречу с видео, raw/clean текстом, спикерами, саммари,
   тегами и highlights. Импортировать в другую тестовую библиотеку, проверить
   playback/seek, повторить импорт и убедиться в предсказуемом пропуске дубликата.
2. Через Library импортировать медиа + готовый SRT/WebVTT и проверить native
   диалоги, текст и таймкоды. Обработка моделями для этого пути не требуется.
   Native importer через IPC, точные данные и настоящий playback/seek до/после
   перезапуска автоматически проверены 2026-11-02; file chooser UX ещё не принят.
3. После явной подготовки локальных моделей создать профиль в Voices. Добавить
   два одноголосых образца из файла/интервала записи, прослушать их, удалить
   неверный образец и пересчитать профиль. На другой контрольной записи проверить
   предложения имён и неизвестного голоса. Качество оценивать на разметке,
   отдельно для выбранных языков и количества участников.

## Внешняя обработка после выбора интеграции

1. На искусственном тексте отдельно выбрать Codex и Claude Code, проверить
   имеющуюся подписочную авторизацию, генерацию, отмену, повторное открытие
   карточки во время задачи и сохранность прежнего саммари при ошибке.
   Проверить длинный искусственный транскрипт в пределах 2 MiB и ошибку сверх
   предела. Настоящие встречи не требуются для проверки интеграции.
2. Soniox проверять после предоставления ключа и явного разрешения в Settings.
   На контрольном аудио проверить live/final, остановку, обрыв/повтор соединения,
   сохранность медиа/подтверждённого текста и явную замену через локальный
   Re-transcribe. Измерить задержку и качество на согласованных примерах.

macOS и другие устройства проверяются отдельно. Факт Windows-сборки не закрывает
эти платформенные проверки. Исходники и контрольные материалы не публикуются.
