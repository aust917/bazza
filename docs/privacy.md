# Privacy

Bazza is built so that you never have to trust anyone with your meetings.

- **Local by default.** Recordings, transcripts, summaries, chats and voice samples stay in your local library unless you explicitly choose an external integration or share action.
- **No account, no telemetry, no crash reporting.** Every network connection Bazza makes is one you can see and turn off:
  - downloading AI models from Hugging Face when you ask;
  - fetching the calendar .ics addresses you pasted (Settings > Calendar), on the schedule you set;
  - POSTing finished meetings to the webhook URL you entered (Settings > Webhook, off by default);
  - talking to a model server you configure yourself (off by default);
  - checking your own Discord bot and the channels it can join when you use Discord settings, and receiving voice tracks directly from Discord when you enable Discord names for a recording;
  - downloading Ubuntu, Attendee source and the packages and container images it needs when you set up the managed Google Meet integration on Windows x64;
  - sending a Google Meet link to your configured Attendee instance and receiving participant names and audio when you enable Google Meet for a recording;
  - streaming recorded microphone and selected system audio to Soniox, only after you save a key, permit processing and select that provider (off by default);
  - sending transcript text through your signed-in Codex or Claude Code CLI when you select that agent and generate a summary. The service library previews the exact text using the excerpt you chose. The classic library sends the transcript and chosen template, which can include meeting details such as participant names;
  - sending your question and the optional text in the subscription form through the selected CLI, only when you press Send. You can paste text or select a range from the current meeting and review it in the editable context field first. The form sends no saved chat history automatically.
- **Attendee names** come from the meeting window on your own screen (Windows accessibility tree) or your calendar event. Bazza stores them with the meeting. Enabled integrations, sharing and explicit summary actions can include them.
- **Discord bot is optional.** Ordinary recordings capture the audio and screen you choose on your computer. If you turn on Discord names in the recording picker, your bot joins the chosen server voice channel when recording starts and leaves at Stop. Bazza writes separate voice tracks and their Discord names to the local meeting folder. The bot token stays in the system credential store and is used to authenticate with Discord. The setup wizard can copy a generic guide for an AI assistant of your choice. The guide contains no token or server details. Paste the token directly into Bazza.
- **Google Meet bot is optional.** When selected in the picker, your Attendee instance joins the call as **Bazza Recorder**. That instance receives the meeting audio and participant metadata and sends them to Bazza through an encrypted connection. Bazza stores the separate WAV files and their names in the local meeting folder and saves the API key in the system credential store. Bazza requests audio streaming with Attendee recording disabled. The bot uses native Meet captions, which your Attendee instance may retain. The selected instance controls its own processing and retention. [Google Meet setup](dev/attendee-integration.md).
- **Managed Attendee runs on your Windows computer.** Selecting **Set up Google Meet** creates a dedicated local WSL 2 environment and generates the API key and TLS certificate. Bazza starts the configured service as needed when you enable Google Meet for a recording. The worker connects to Google Meet and sends audio back to Bazza through the local WSL network. If you connect your own remote Attendee instance through advanced settings, that instance handles the audio and metadata. [Google Meet setup](dev/attendee-integration.md).
- **No automatic update requests.** This local build has no update endpoint or upstream signing key.
- **Visible recording sources.** The picker shows which display supplies video and which devices supply audio. When system audio is enabled, Bazza records everything played through the selected output, including sounds from other applications.
- **Manual.** Detection shows a prompt. The idle recording hotkey opens the setup screen. Capture starts when you choose Record. Speaker names are suggestions until you confirm. Share links exist only when you create them, on your network, while Bazza is open.
- **Explicit transcription choice.** Local Whisper remains the default. With Soniox selected, confirmed captions and provider provenance are saved locally; a connection failure leaves media and confirmed text intact. Partial text is not promoted to final text. Re-transcribe explicitly selects local Whisper.
- **Participant-track transcription is local.** During a recording with a Discord or Google Meet bot, the installed Whisper model uses the separate audio streams and their display names. Completed live captions are kept as the initial transcript. The explicit action on a completed meeting uses local Whisper to save a separate transcript. In the legacy desktop, an opt-in Soniox session can also receive the microphone and selected system audio mix. The managed desktop uses only Local Whisper when recording with a bot.
- **Revocable cloud capture.** Switching to Local, turning off Soniox consent, or clearing its key stops the current cloud worker while local recording continues. Confirmed text remains; a local re-transcription is a separate action.
- **Voice memory stays separate.** Managed speech samples and voiceprints remain local and are excluded from `.bazza` recording exports. Soniox credentials are stored separately in the library database, never returned by ordinary settings or included in recording bundles.
- **MCP access is explicit.** A service library exposes a local MCP connection only when its owner enables the separate read endpoint and grants access to a client. The grant covers the library's meeting metadata, transcripts, summaries, notes and organization. It does not expose media files, settings or provider keys. You can revoke the grant; what the MCP host does with data it already read depends on that host.
- **Local MCP clients on Windows.** A fresh installation starts with access off. The interactive installer offers opt-in access to Codex and to Claude Code and Claude Desktop. In-place updates preserve existing grants. Each client has a separate read credential in Windows Credential Manager. Windows can start the library service while Bazza is closed. Turning a client off in Bazza Settings revokes its grant and removes the entry created by the installer for that client.
- **Agent summaries are explicit.** Transcript and speaker edits preserve an existing agent summary until you choose to regenerate it. Cleanup, titles, ordinary chat and live notes continue using the configured local/endpoint language model.
- **Nothing lingers after a crash.** The screen recorder is tied to Bazza's own process, so it cannot keep capturing if Bazza dies; the interrupted recording is finished from disk on the next launch.

Recording other people may require their consent depending on where you are. Bazza makes that easy to do properly, but it is your responsibility.
