# Прототип записи Discord для Bazza

Локальная утилита на Serenity и Songbird 0.6.1. По команде `record` бот входит в указанный серверный голосовой канал, связывает входящие аудиопотоки с Discord ID и пишет отдельные WAV. Команда `transcribe` распознаёт дорожки локальным Whisper и сохраняет общий транскрипт с именами и временными метками.

В настольной Bazza подключение доступно в **Настройки → Discord**. Введите токен своего бота, при необходимости пригласите его на сервер и выберите обычный голосовой канал. Затем в окне записи включите **«Имена из Discord»** и проверьте выбранный канал. Бот входит при старте записи, пропускает звук на паузе и выходит при остановке. Дорожки с именами сохраняются в папке `discord` внутри записи. Основной транскрипт пока обрабатывается по обычной звуковой дорожке Bazza.

## Подготовка бота

1. В [Discord Developer Portal](https://discord.com/developers/applications) создайте тестовое приложение `Bazza Voice Probe`. На вкладке **Bot** получите токен. Вводите его только в локальный запрос PowerShell из плана проверки.
2. Настройте **Guild Install** со scope `bot` и правами `View Channel` и `Connect`. Установите приложение на тестовый сервер. Ограничьте доступ роли бота выделенным голосовым каналом с помощью прав канала. Для прототипа достаточно `GUILDS` и `GUILD_VOICE_STATES`, которые не требуют включения Privileged Gateway Intents. [Установка и права Discord](https://docs.discord.com/developers/quick-start/getting-started).
3. Из ссылки на голосовой канал возьмите ID сервера и канала (`discord.com/channels/<сервер>/<канал>`). Согласуйте запись с участниками и следуйте [плану проверки перекрытий](../../docs/dev/test-plans/2026-11-03-discord-bot-overlap.md).

## Сборка

Из корня Bazza выполните `cargo build --locked --manifest-path tools/bazza-discord-probe/Cargo.toml --features transcribe`. На Windows нужны Rust, MSVC и CMake. Для сборки с Whisper также нужен libclang. На машине с уже настроенным локальным инструментарием Bazza сначала выполните `. ./.git/local-tools/build-env.ps1`. На Windows бинарник появится в `tools/bazza-discord-probe/target/debug/bazza-discord-probe.exe`. [Среда сборки Bazza](../../docs/dev/testing.md).

```text
bazza-discord-probe record <guild-id> <channel-id> <new-output-dir> [duration-seconds]
bazza-discord-probe transcribe <tracks-dir> <model-file> [language]
```

`record` читает `BAZZA_DISCORD_BOT_TOKEN` из окружения. По умолчанию бот слушает 60 секунд, допустимый диапазон от 1 до 3600 секунд. Ctrl+C завершает запись и сохраняет WAV. Для `transcribe` нужен файл модели Whisper, например `ggml-small.bin` из локальной папки моделей Bazza. Команда принимает записи до 10 минут, сохраняет перекрывающиеся сегменты и пишет `transcript.json`.

## Воспроизведение сценария несколькими ботами

Используйте 2, 8 или 16 отдельных приложений Discord с bot user. Приёмник должен быть отдельным ботом. Для отправителей нужны права `View Channel`, `Connect` и `Speak` в одном обычном голосовом канале. В канале должно быть место для всех отправителей и приёмника. Для прогона с 16 говорящими не добавляйте других источников речи, чтобы не превысить лимит записи. [Права Discord](https://docs.discord.com/developers/topics/permissions) · [Шифрование голосовых кадров DAVE](https://docs.discord.com/developers/topics/voice-connections#end-to-end-encryption-dave-protocol)

```text
bazza-discord-probe validate-scenario <scenario.json>
bazza-discord-probe send-scenario <guild-id> <channel-id> <scenario.json> <credentials.json|-> <new-report.json>
```

Проверку сценария запускайте перед подключением. Утилита читает `scenario-{2,8,16}.json` из локального корпуса, сверяет участников, события `join` и `leave` и WAV. Поддерживаются моно и стерео PCM16 на 24 или 48 кГц. Пути WAV задаются относительно JSON. `at_ms` отсчитывается от начала сценария, а `speech_start_ms` и `speech_end_ms` задают границы речи внутри клипа. Отдельно запустите приёмник с запасом времени. Дождитесь подключения к каналу, затем запускайте отправителей. Для прогона с 16 дорожками длительностью 30 минут понадобится около 2,8 ГБ только под Discord WAV.

Передайте `-` вместо пути, чтобы прочитать JSON из stdin. Подайте UTF-8 JSON без BOM из локального хранилища через pipe и закройте поток. Если используете файл, храните его в локальной папке, исключённой из Git. Для обоих способов действует предел 64 КиБ. Для каждого `participant_id` нужен отдельный числовой ID приложения Discord в виде строки и его токен. ID в примере условный.

```json
{
  "participants": [
    {
      "participant_id": "p01",
      "bot_id": "111111111111111111",
      "token": "<bot-token>"
    }
  ]
}
```

Отчёт связывает участников сценария с подтверждёнными ID ботов и сохраняет плановое время, время передачи команды и наблюдения локального микшера Songbird. Метки в миллисекундах измеряются монотонными часами относительно начала сценария. `scenario_started_unix_us` даёт UTC-якорь для приблизительного сравнения с часами приёмника. Наблюдение микшера показывает локальный ход воспроизведения. Приём аудио и идентификацию говорящих проверяйте по WAV и манифесту приёмника, особенно сразу после входа или выхода участников.

## Как читать результат

- `<user-id>.wav` содержит 48 кГц mono PCM16. Все дорожки начинаются с одного 20-мс тика и дополняются тишиной до общей длины. Шкала отражает время воспроизведения пакетов у бота с учётом его буфера, поэтому небольшое смещение относительно микрофонов участников возможно.
- `tracks.json` содержит состояние остановки, длительность, соответствие ID, имён и файлов и счётчики пропусков. Имя берётся из профиля участника на сервере после записи. Если запрос не удался, останется `Discord <ID>`. Извлечение имени следует проверять отдельно от правильного определения ID.
- `dropped_ticks` считает переполнение очереди записи, `unmapped_frames` — пакеты с ещё неизвестным источником, `invalid_frames` — принятые кадры с длиной или форматом вне ожиданий прототипа. Прототип принимает стандартные 20-мс кадры, а большие кадры и подстановки при потере пакетов пропускает. DAVE также может отбросить кадр до вызова обработчика. Сверяйте файлы с контрольными репликами даже при нулевых счётчиках.
- При выходе, перемещении или разрыве связи бот завершает приём. WAV и манифест могут содержать только записанную часть. При сбое записи на диск комплект файлов следует считать неполным, если итоговый `tracks.json` отсутствует.
- В новых манифестах v1 поле `timeline` хранит UTC-якорь попытки (`attempt_started_unix_us`) и монотонные метки в микросекундах от него. `spans` сопоставляет полуоткрытые интервалы тиков WAV с первым и последним наблюдением голосового callback. Пауза и промежуток между callback больше 60 мс начинают новый интервал. `writer_drops` отмечает тики, потерянные из-за переполнения очереди. Если диапазоны достигли лимита, `truncated` отмечает неполные данные. Дорожки также содержат первый и последний принятые тики своего Discord ID.
- Время первого тика показывает, когда приёмник начал наблюдать голосовые события после подключения. `capture_closed_elapsed_us` фиксирует закрытие захвата перед выходом из канала и запросом имён. Для сравнения со шкалой `mix.wav` используйте её отдельный якорь `mix.clock.json`. Тик WAV равен 20 мс, а точность сравнения зависит от буфера Discord, планирования событий, часов и границ паузы. Время тика показывает локальное наблюдение, поэтому его нельзя считать моментом речи или доказательством точного совпадения с записью ПК.
- При предварительном подключении Discord подтверждает вход бота в канал через Gateway. После «Записать» Bazza открывает приём медиа на том же подключении и создаёт каталог WAV. В `timeline` дополнительно сохраняются `local_epoch_unix_us` и `local_epoch_elapsed_us` из общей отметки старта локальной записи. Первый приём PCM может начаться позже этой отметки, пока устанавливается голосовой транспорт.

Прототип рассчитан на один обычный серверный голосовой канал и до 16 говорящих аккаунтов за прогон. Записывайте тесты в новую папку вне репозитория и храните аудио и транскрипт локально.
